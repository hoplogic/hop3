# CLI 定位（`<CLI>` / `<PKG>`）

> 一条命令定位，找不到直接报错（2026-08-09 作者定——原四级探测阶梯废除：现实安装只有 `npm i -g` 与开发期 `npm link` 两种，都落在全局命令上；多级"可能装法"纯属想象出的复杂度，且诱导过三次探测事故：命中后继续翻下级、固化裸字、跨 shell PATH 漂移）。

## 定位算法（一条，命中即完、不中即停）

```bash
command -v hopjit
```

⚠️ **这条命令必须单独成条**——禁止与任何其它命令链式合并（`&&`/`;`/管道）。实撞（2026-08-09）：与 recent-dirs 读取合并成 `command -v hopjit && if test -f ...` 一条后整条无输出，被误判"未安装"向用户误报——链式的另一半会吞掉/短路输出，定位结果不可信。

- **有输出** → `<CLI>` = 输出的那个**绝对路径**（禁止固化裸字 `hopjit`——subagent shell 不保证继承 PATH）。**到此为止，不做任何其它探测。**
- **无输出** → 先**单独重跑一次** `command -v hopjit`（防上一条被环境瞬态/输出通道问题吞掉——实撞过"命令实际可解析但一次调用无输出"）；仍无输出才**报错停止**，向用户说明：
  - 使用者：`npm i -g @hoplogic/hopjit`
  - 开发者（hopjit 仓库内）：`npm run dev:install`（内含 build + link）
  - 装完重试。**禁止**替用户翻 node_modules、项目 dist 等目录找替代入口——那是装没装好的问题，掩盖它只会把故障搬到更晚更难查的位置。

## `<PKG>`（仅在需要引用引擎包内文件时取）

```bash
npm root -g
```

`<PKG>` = `<npm root -g 输出>/@hoplogic/hopjit`。**具名 skill（spec 在自身目录）与 `run <明确路径>` 用不到 `<PKG>`——禁止取**（不跑 npm root -g，一条多余命令都不跑）；只有确实要引用 `<PKG>/examples/...` 这类引擎自带资源时才跑这一条。

## 纪律

- 定位静默完成，一行结论（如"引擎：hopjit 0.2.0"）；本会话固化，不重复定位。
- 传给执行 subagent 的 prompt 里 `<CLI>` 原样嵌入绝对路径。

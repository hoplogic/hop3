# 工程实现链 · 守卫规范

> **定位**：工程实现链的**守卫级概念权威**——回答"链凭什么被相信：什么会腐坏、由谁守、守卫自身凭什么可信、**守到什么程度才算数**"。[[工程实现链规范]] 定义链的结构与作业纪律，[[工程实现链-模块规范]] 定义横向封装单元，本规范定义**防腐机制**：没有它，前两者的一切约定只是愿望。
>
> **分工**：本文档管**概念级原则**（通用方法论，与具体项目无关）；某项目的具体守卫映射表、工具、台账、执行时机属其设计层（本库见 [[code/hopstep/design/chain-enforcement|chain-enforcement]]）。下游引用本规范，不复制规定。

## 一、为什么需要守卫：腐坏默认无声 ^anc-guard-why

链的静态结构（分层、锚点、模块）与作业纪律（宪法、协议）都不会自动维持——**链会腐坏，且腐坏不产生任何即时可见的错误**：锚点悬空、设计与代码漂移、守卫自身失效，全部静默发生。等到被察觉时，漂移已沿层级放大成事故。

守卫体系因此不是工程附件，而是**元规范自身完整性的承诺**。三者关系：分层/锚点/模块定义**链是什么**，宪法/协议定义**怎么作业**，守卫体系定义**凭什么相信前两者被持续遵守**——三者合一，链才自洽。

## 二、三条原则 ^anc-guard-principles

（2026-08-08 作者审定重构，编号均指**旧五条**：旧 1「映射」与旧 3「台账」是同一件事的两个断面，合并为新 1「显式覆盖」；旧 5「准入」是旧 1 与旧 4「自证」的推演产物被误立为原则，删除、其判定句降为本节末推论。`^anc-meta-guard-*` 锚点在 [[工程实现链规范]] 指针桩原位保留。）

### 1. 显式覆盖：每一环显式回答"由谁守、何时执行" ^anc-guard-mapping

链的每个环节——层内合规、层间跃迁、宪法原则、横向模块环——要么有守卫、要么显式声明不守。**不允许"没想过"的默认裸奔**。"由谁守"的完整回答天然包含"何时执行"：永远不被执行的守卫等于没有守卫，把它填进映射表就是假回答。

回答"不守"必须是显式决定，不是遗漏的别名——未被守护的环节入台账，每项处置三选一： ^anc-guard-gap-discipline

- **补守卫**：带验收标准；
- **接受不守**：记 why + 复审触发条件（合法状态——不是所有环节都值得守，成本/收益归人判）；
- **待定**：必须带截止条件（到点转前两者之一）。

**映射表与台账是同一张表的两个视图**：映射表管"每环都答了吗"（空格即违规），台账就是其中状态≠"已守"的行（管"答'不守'的项处置了吗"）。

### 2. 手段与对象的类型学：行为不可直接守 ^anc-guard-three-kinds

两个正交维度，混淆即自欺：

**守卫手段二分**（按判定者）：

| 手段 | 判定者 | 特征 |
|---|---|---|
| **确定性机检** | 脚本 | 有唯一正确答案 |
| **语义审计** | LLM/人（读源理解意图） | 无唯一答案，判"忠实/对齐"——**评审是语义审计的人工形态** |

只有这两种手段。**机检全绿≠链健康**——机检只覆盖有唯一答案的部分。

**被守对象二分**（按可观测性）：

| 对象 | 可观测性 | 怎么守 |
|---|---|---|
| **产物**（文档/代码/测试/表） | 可直接检查 | 手段直接作用其上 |
| **行为**（收链前置/设计先行等动作纪律） | **不可直接观测**（动作在过程里，不留痕迹） | 只能守其**产物投影**——每条行为纪律必须声明它的产物侧信号（如"设计先行"→"src 改而 design 未改"机检信号；"收链前置"→锚点漂移语义审计） |

**行为不是第三种守卫手段，而是一类被守对象**；宣称某条行为纪律"靠自觉"就是没有守卫——无产物侧信号的行为纪律，按原则 1 属"默认裸奔"，必须入台账。

### 3. 守卫自证：守卫自身没有防线 ^anc-guard-self-trust

守卫会坏且坏了默认无声（判据配置错、静默跳过、假绿）。四条硬要求：

1. **负向验证**：新守卫必须故意制造违规确认真的红——只验证"当前通过"等于什么都没验证；
2. **判据回归（正反例成对常驻）**：守卫的判据逻辑自身要有测试，且**正例（该过的过）与反例（该拒的拒）必须成对**——一次性负向验证 ≠ 常驻保护；只有正例的判据测试同样不算数（豁免外溢、拦截漏放、修复误伤相邻语义，全部只有反例测得出）。判定/豁免规则每次变更，反例优先钉在**动过的边界**上（改了豁免就测豁免不外溢、改了轮次判定就测相邻 resume 语义不被误伤）。上游测试原则见 [[工程实现链规范#^anc-meta-layer-test]] 正反例成对条（2026-08-10 实撞入法：--answer 豁免上线时零测试、hoplog #iter 修复只有正例，作者两连追问补齐——判定变更不带反例是常态漏法，故升为守卫硬要求）；
3. **禁静默跳过**：依赖缺失必须显式失败并给修法，不得 skip 冒充通过；
4. **输出零假警报**：测试中故意触发的错误与被测工具的正常警告必须捕获，不得直通输出——绿灯跑出满屏 Error 会让人分不清真假。

**三原则正交**：1=覆盖义务（每环有守卫），2=类型学（什么手段守什么对象），3=自反性（守卫自身也被守）。

**推论（无宽限期）**：原则自守卫诞生一刻即生效——未入映射（原则 1）、未自证（原则 3）的守卫**视同不存在**，与"缺锚点即缺追溯"同一逻辑；堵住"守卫临场发挥、挂哪儿看心情"的增量腐坏。 ^anc-guard-admission

## 三、审计的两个维度：纵向锚点链 × 横向模块边界契约 ^anc-guard-anchor-chain

（2026-08-08 作者定：审计有两个维度——纵向是锚点链，横向是模块边界契约。此前规范只提了纵向的一半。）

**语义审计不能凭空作业**——判断"忠实/对齐"的前提是知道**什么该与什么对齐**。这个对应关系有两套物理载体，对应审计的两个维度：

**纵向维度：锚点链**（沿抽象度，定义见 [[工程实现链规范#^anc-meta-traceability]]）——`^anc-*` → `@a:` → `@v:` 把概念/设计/代码/测试逐层缝合：

- **没有锚点链，纵向审计退化为通读**——审计者只能把两层文档全文对读碰运气，注意力成本不可承受且必然漏；有锚点链，审计收窄为逐锚点的定点比对（S→D / D→C / C→T 三段，每段有限而完整）；
- **审计必须全量、最严格**：任一锚点不对齐都沿层级向下放大（宪法级"锚点对齐"条款）——纵向审计不抽样。

**横向维度：模块边界契约**（沿封装边界，定义见 [[工程实现链-模块规范]]）——边界声明（含"不碰"去向）、出口清单【封闭】、`@module:` 归属、依赖方向共同划定"谁能碰什么"：

- 横向审计判的是**越界与缝隙**：import 了出口表外的符号（边界违规）、出口无消费方（接口面虚胖）、依赖方向逆行、文件无归属、两模块间的无主缝隙（都以为对方管）——这些纵向锚点链**看不见**（每个模块各自纵向对齐良好，横向照样可以彼此越界）；
- 纵向链每环都齐、横向不合规，链仍不完整——两维正交，缺谁都是盲区。

**审计的作业单位 = 模块**（2026-08-08 作者定）：两维不是分开跑两遍——审计**按模块为单位组织**，对每个模块审它的锚点链。一个模块的审计单元 = 该模块的设计契约锚点 + 代码 `@a:` 落点 + 测试 `@v:` 落点（纵向段）+ 它的边界契约（横向面），恰好就是"注意力自足"承诺的那个独立可理解单元——**模块怎么切，审计就怎么分片**。这样每片审计装得进一个上下文窗口（语义审计者同样是有限主体，注意力经济对审计者一样成立）；全库审计 = 逐模块分片之和 + 跨模块横向缝隙检查，而非一次性全库通读。反过来这也是对模块切分质量的持续检验：某模块的审计单元装不进窗口，即模块过大的拆分信号。

**两维的载体自身都是被守对象**（产物类，原则 2 的直接应用）：锚点悬空/缺锚/格式违规，出口表过期/归属缺失/依赖声明与实际不符——都是机检可判的确定性问题。**载体完整性靠机检守，载体之上的语义对齐靠审计守**，两层手段各司其职。

## 四、失效对治与日常守卫 ^anc-guard-failure-backstop

三类作业失效（可行域漂移/跨层直达/角色混淆）的对治都是**行为纪律**——按原则 2，行为不可直接守，每条必须有产物投影上的守卫手段接住（纪律管"别犯"，产物侧守卫管"犯了会红"）：

| 失效 | 行为纪律（被守对象） | 产物侧信号 + 守卫手段 |
|---|---|---|
| 跨层直达 | 设计先行 | src 改而对应 design 未改 → **机检** |
| 可行域漂移 | 收链前置 | 代码与上层锚点漂移 → **语义审计**（事后暴露） |
| 角色混淆 | 决策先对齐 | 【决策】章节被改动 → **语义审计·评审形态**（作者确认） |

哪条行为纪律缺产物侧信号，按原则 1 台账纪律显式登记，不许默认裸奔。

**测试层的日常守卫**（终点的前置过滤器） ^anc-guard-test-side：

- **覆盖率基线只升不降**：仓库锁定行/分支覆盖率基线，机检保证不降（提升后人工上调，不自动放松）。覆盖率是底线不是目标——数字达标不等于关键路径被真验证。

## 五、守卫链的终点：e2e 实测 + hoplog 分析确认 ^anc-guard-e2e-primacy

（2026-08-08 作者定：守卫链必须以此为**终点**——此前规范只罗列守卫种类、没有立终点。）

**静态守卫与单元测试证明不了系统真的能跑**。机检证明格式与结构合规，语义审计证明各层表述对齐，单元测试证明模块行为符合契约——但"合规+对齐+模块各自正确"加起来**不等于**端到端真实运行成功：真实宿主进程、真实模型往返、真实协议时序、真实文件系统副作用，只有真机实测能覆盖。

> **守卫链的终点 = e2e 实测 + hoplog 分析确认**——两个成分缺一不算到达终点：实测给出"结果对了"，hoplog 分析给出"过程也对了"。其余一切守卫都是通往终点的前置过滤器（省实测的钱、缩定位面），不是终点的替代品。

**为什么终点必须含 hoplog 分析**：只看终态输出，过程走歪测不出来——中间步被跳过、顺序错、该暂停没暂停、执行体归属错误、轨迹缺失，都能藏在一个"看起来正确"的最终结果后面（实证：真机 e2e 业务结果全对、唯 hoplog 轨迹缺失——若无 hoplog 分析这一环，驱动协议漏参数的回归就随"结果正确"漂过去了）。hoplog 是执行过程的唯一权威记录，对它的分析确认是过程正确性的唯一证据形态。

四条硬要求：

1. **hoplog 由生产代码真写、分析逐步骤核对**：过程凭证必须由生产执行路径写出（守卫拿自造格式自证=自欺，见原则 3）；分析按"状态里每个完成步骤在 hoplog 有精确轨迹"逐一核对，缺一步即红——不做子串匹配式的宽松确认；
2. **真环境、不用替身**：真宿主/载体进程、真模型调用、真凭证链路——mock 掉任何一环，该环的回归就永久盲区（实证：五轮真机 e2e 连续揪出四类静态全绿的真缺陷——provider 侧 400、驱动协议漏参、守卫正则过时、路径解析漂移——每一个都是"单测千绿、真机即死"）；
3. **终点守卫是 release 的硬性准入闸**（2026-08-08 作者定）：release（发版/发布/部署等一切不可逆外向操作）**必须机检核验终点凭证**——e2e 实测 + hoplog 分析确认通过时自动落盘的凭证，须**在场且指向当前版本**，缺失或过期（实测后又有变更）即中断 release，**无跳过路径、续发/重跑模式同样不豁免**。凭证只能由通过动作写出（人工不可伪造出"通过"）。**写在手册里的"发版前必须实测"没有机检=会被跳过**（实证：手册纪律被绕过，真回归差点带版发出；升级为凭证机检闸后才真正守住——原则 2"行为纪律必须有产物侧信号"的范例）；
4. **Agent 环境受限不豁免终点，绝不糊弄**（2026-08-08 作者定）：Agent 自己的环境跑不了实测（沙箱禁进程、缺凭证、缺真机）时，**唯一正确动作是把实测做成人可一键执行的脚本**（批量全场景、结果落文件、凭证自动落盘——人只出终端和凭证，其余全部脚本化），并如实声明"我没跑、需要你跑"。**禁止**：拿预演/清单核对/静态检查冒充实测；说"只能在你终端跑"却不递上可执行的命令；用部分事实制造"已验证"的印象。实证：agent 以"预演过清单"含混带过未实测状态，真回归差点带版发出——环境受限是事实，糊弄是选择；前者无罪，后者即失职。

**终点的执行方案：真机三档**（2026-08-14 作者拍——终点原则此前只立"必须实测",没立"怎么组织实测";4 个批量入口按内容分批与 5c 成本分档两维打架,收敛为单一成本维度三档,方案权威在本节,本库操作化=carrier-live-e2e §6 三档表）：

| 档 | 语义 | 时机 |
|---|---|---|
| **例行档 smoke** | 引擎-工具-server 真机面（无载体进程,零/单 LLM,分钟级） | 改引擎后随手跑,天天跑得起 |
| **发版档 core** | 载体协议与执行链**正确性**（快乐路径+失败路径全量,并发跑;终点凭证在此落盘） | 发版前必跑——就是硬要求 3 那道闸的凭证生产动作 |
| **触发档 deep** | **LLM 质量面**（深核判定/文档教学力/弱模型长程——不随引擎小改回归） | 按触发条款跑:改了对应面才跑,不进例行 |

分档判据=**测的是什么**而非"贵不贵"：正确性面（smoke/core）随代码改动回归,必须例行/发版覆盖；质量面（deep）随 prompt/文档/模型面改动回归,例行跑它是烧钱不增信。并发是档内优化（共享面互斥先核清——全局配置类共享状态须调度层互斥,不可假设"各场景天然隔离"）。

### 5a. 判卷者也在链上：断言载体是契约消费者 ^anc-guard-assertion-on-chain

（2026-08-11 作者定，实撞入法：e2e 断言库查"父账恰 1 个 failed child"——旧通道账面形状假设；统一模型语义迁移改遍全库，唯独它幸免——**零锚点故 review 收链收不到、不进 vitest 故改漏不红**，静默潜伏到真机人工触发才暴露。同函数内另一半断言因 grep 得到旧通道特征词被改掉，恰证明"靠肉眼认旧形状"不是守卫。）

**一切断言载体（单元测试、e2e 断言脚本、审计 spec 判据）都是上游契约的消费者，与代码同等在链上**。两条硬要求：

1. **断言挂锚点**：断言逻辑绑定哪条契约就挂哪条的 `@v:`——语义迁移时收链能收到它，不靠肉眼认旧形状；
2. **断言可执行或可重放**：不被例行执行的断言=没有断言（原则 1"永不执行的守卫等于没有守卫"对断言同样成立）。执行成本高的断言（真机 e2e）必须有**存档重放**兜底——拿既有通过存档（脱敏 state+hoplog）干跑断言逻辑，语义一改、断言过时当场红，不烧真机。

### 5b. 沙箱等价优先：真机只留不可替代的那一环 ^anc-guard-sandbox-equivalence

（2026-08-11 作者定："所有真机跑的例子，在 vitest 里也应该尽可能的都测试掉，不要留雷"。）

真机场景覆盖的语义 = 引擎语义 × 协议时序 × 断言逻辑 × 真 LLM/载体行为。**前三者全部可沙箱化，必须在单元/集成测试里等价覆盖**——真机只保留"真模型往返、真载体进程、真凭证链路"这不可替代的一环。判据：真机红了而沙箱全绿时，差因必须落在不可替代环内；若差因是可沙箱化的部分（引擎语义、时序模拟、断言形状），即欠一笔沙箱等价债，按台账纪律入账。

### 5b-2. mock 盲区反向义务：真机必须覆盖所有 mock 的坑 ^anc-guard-mock-blindspot

（2026-08-14 作者定："在守卫链加上，e2e 测试必须要覆盖所有 mock 的坑"——BUG-H 实撞：standalone 大输入 deflate 成 $file 指针泄给裸 API LLM，三层测试全绿放行——vitest 的 LLM 全 mock 不消费 prompt 内容、真机 e2e 场景矩阵没有"standalone×超阈大输入"一格、等价台账上这一格两边都没登记＝没人知道它没被测。）

5b 说"真机场景尽量沙箱化"；本条是它的**对偶方向**：**mock 天然失明的断言面，必须有真机场景显式覆盖，且在等价台账上成对登记**。作业协议：

1. **识别 mock 盲区**：每引入一个 mock（假 LLM/假工具/假载体），问一句"它对什么失明"——mock LLM 不消费 prompt 内容（指针/真值不辨、截断不辨）、mock 工具不验实参形状、假载体不验进程行为。失明面逐条写进等价台账"真机不可替代环"列；
2. **真机场景对表补格**：台账里每一条失明面必须能指到一个真机场景+断言；指不到＝场景矩阵缺格，补场景或立账，不许空白无声；
3. **可机检的部分就地机检**：失明面中可用产物侧信号核的（如 input_tokens 与输入量级相称——BUG-H 哨兵），断言直接进真机 runner，不留人工抽查；
4. **mock 能验的注入面就地补**：mock 验不了"LLM 真消费"，但验得了"注入面给了什么"（prompt 文本断言）——这层沙箱能做，属 5b 义务不豁免。
5. **否定式不变量成对（2026-08-14 作者追问"反例也没挖出来"的答案沉淀）**：反例只能打有靶的枪——BUG-H 前 38 个反例零命中,不是断言技术缺（mock 实收 prompt 的断言手段一直在用）,是**错误模型里没有这类错**："prompt 含指针"当时是设计内行为,没人给正确行为写反例。故：**跨模式/跨消费端机制的每条隐含前提,显式化时必须配一条否定式不变量**（"X 不得出现在 Y"——如 `$file` 不得出现在裸 API prompt）,反例据此有靶;只写正向断言（"该有的在场"）不算成对。夹具尺寸同查：不变量涉及阈值行为的,夹具必须双侧取值（阈上+阈下）,小输入惯性会让阈上分支永不执行。

### 5c. 实测例行分档：轻档例行跑，重档发版跑 ^anc-guard-e2e-tiering

（2026-08-11 作者定："能够控制在 5 个 LLM 交互内的，应该例行跑；MCP 的例子可以直接跑"。）

真机实测按成本分档，不是铁板一块地全压到发版前：

- **例行档**：≤5 次 LLM 交互的场景 + MCP 可编程直跑的例子——成本分钟级/角分级，纳入日常节奏例行执行，回归当天暴露而非发版日集中撞雷；
- **重档**（长流程、多轮编排、全量审计）：发版闸/按需跑。

分档的目的与 5a/5b 同源：**缩短"断言/语义漂移 → 被发现"的时延**——例行档天天跑，漂移潜伏期从"到下次发版"缩到"到当天"。

## 六、守卫链的整体闭环：每一环凭什么被保障 ^anc-guard-chain-closure

（2026-08-08 作者指出缺严重逻辑闭环并要求具体化：守卫要求很多、审计有方法论、终点也立了——守卫链**作为整体**如何保障每一环，必须落到**具体概念工具与生命周期时机**，不许泛泛。）

### 闭环的构成：规则 × 制品 × 工具 ^anc-guard-closure-tools

三类东西性质不同，闭环靠三者咬合——**规则定义"什么算对"，制品承载"当前状态"，工具执行"检查与产出"**（把制品当工具、把产出物当机制，闭环就是纸面闭环）：

**规则（定义层）**：

- **环全集推导规则**：枚举公式——纵向 = 3 段跃迁（S→D/D→C/C→T）+ 4 层各自层内合规；横向 = 每模块 × 边界契约件（边界声明/出口表/归属/依赖方向）；再加宪法逐条 + 行为纪律逐条（各带产物投影信号）。结构变（加层/加模块/加纪律）全集即变——可推导，遗漏才可判定。

**制品（状态层，被工具检查、被协议维护）**：

| 制品 | 形态 | 承载什么 | 谁检查它 |
|---|---|---|---|
| **守卫映射表** | 实体表：环 × 守卫 × 手段 × 时机 × 判据锚点 | 已知的环各由谁守 | 差集工具（见下） |
| **空白台账** | 映射表状态≠"已守"行的视图 + 处置字段 | 放弃/待定是显式的 | 台账复审（周期性时机） |
| **终点凭证** | 终点守卫通过时自动落盘的文件（版本+时间戳） | 全链总验的最近一次通过证据 | release 闸工具 |

**工具（执行层，可跑、产出判定）**：

| 工具类 | 干什么 | 手段类型 |
|---|---|---|
| **机检脚本群** | 格式/锚点/分层/归属/版本互锁等确定性判据，逐环红绿 | 机检 |
| **差集检查** | 环全集推导结果 vs 映射表登记比对，差集非空即红（守"表自身不烂"） | 机检 |
| **语义审计工具** | 按模块分片读源判"忠实/对齐"（§三作业单位）。⚠️ 实践中此类工具常被打包成"审计全家桶"（扫描+比对+语义+修复一个名字）——**必须按本表性质拆开对待**：扫描/比对是机检、修复是写操作，只有读源判忠实这一块才是语义审计；混称会让节奏闸核错产物（实证：闸核了机检产物→恒绿假闸） | 语义审计 |
| **e2e 实测驱动 + hoplog 分析器** | 真机跑全链 + 逐步骤核对轨迹，通过即落盘终点凭证 | 终点（§五） |
| **release 闸** | 机检终点凭证在场且指向当前版本，缺/过期即中断 | 机检 |
| **统一入口命令** | 一键跑完某时机档的全部守卫（如全场景 e2e 批量、全量检查）——人不需要记得单独跑谁、逐个跑谁；批量执行/结果落文件/凭证自动落盘都归它编排 | 编排（把上述工具挂进时机档的载体） |

闭环的成立条件一句话：**规则可推导全集，制品如实记状态，工具挂进时机真在跑**——三层各司其职，任一层缺位或冒充另一层，闭环即假。

### 生命周期时机表（每个时机 = 一个具体触发点 × 跑什么 × 为何在这） ^anc-guard-closure-timing

守卫不是常驻进程，是**挂在工程生命周期具体时刻的检查点**。概念级时机六档（项目按此模板落自己的命令与耗时——本表定"什么时机必须守什么"，工具选型归设计层）：

| 时机 | 触发点 | 必须跑什么 | 为何是这个时机 |
|---|---|---|---|
| **改动中** | 每次代码/文档改完随手 | 快速机检（类型/格式/锚点格式/载体 lint） | 秒级无成本，错误就地消灭不过夜 |
| **提交前** | 每次 commit | 快速机检 + **设计先行判据**（本次改动 src 动而 design 未动=红） | 跨层直达只有在 commit 粒度可判 |
| **推送/合并前** | push / PR | 全量机检 + 全部单元测试 + 锚点审计基线 | 慢检查不该阻塞每次 commit，但不许出本机 |
| **结构变更时** | 新增模块/层/纪律/守卫 | 环全集重推导 + 映射表登记 + 新守卫负向验证（无宽限期推论的执行点） | 结构件诞生的一刻就是新环诞生的一刻 |
| **发版前** | release（不可逆外向操作） | 终点凭证机检（在场+指向当前版本）+ 资产清单核对 | 不可逆点前的最后一道闸，无跳过路径 |
| **周期性** | 月度/里程碑 | 全量语义审计（按模块分片，§三作业单位）+ 台账复审（待定项到期处置） | 语义漂移与台账腐坏是慢变量，机检抓不到、事件触发不了 |

**时机表的完备性判据**：每个映射表内的守卫必须能指认自己挂在上表哪一档、经哪条统一入口命令被执行——指认不出=不在岗=视同不存在（无宽限期推论）。每档时机应有且仅有一条入口命令（人与自动化共用同一套，杜绝"CI 跑的和本地跑的不一样"）。

### 闭环自检句

任取链上一环，五步走通：**推导规则能枚举出它 → 映射表有它的登记 → 登记指认了时机档 → 该档的工具真在跑 → 万一全漏还有终点黑箱兜底**。走不通的那一步，就是当下最该修的洞。

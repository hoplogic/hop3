# HopSpec 核心创新

## 定位

HopSpec 是双态通用编程语言：代码逻辑与 LLM 推理在同一套语法中无缝混合，供人对齐意图，供机编排执行，供业务持续演进。

当前自主 Agent 处理任务面临两个核心痛点：
+ **生产型任务不可靠**——当前纯自然语言 skill 缺乏双态融合支持，子任务执行完整比例普遍不到 85%，LLM 步骤静默失败、结果无核验、异常无修复路径；
+ **探索型任务不安全**——可逆操作（试算、草稿）与不可逆操作（发邮件、写库、支付）不加区分，agent 尝试探索过程中往往导致不可逆的严重后果。

HopSpec 中的 Spec 即规约——人与 LLM 之间关于任务目标、约束和交付的契约。Goal/Constraints/Outputs 构成不可违反的契约条款，Steps 是在契约边界内可调整的执行路径。Spec 有两种形态：有 Steps 的具体实现，和无 Steps 的 **HopTrait（Hop契约）**——仅定义接口契约，由 HopJIT 有序思考生成路径或从 Spec 库匹配。

## 价值主张

- **供人对齐——结构化逻辑、显性控制** ：HopSpec 用自然语言描述任务逻辑，不需要编程背景就能审查、确认和参与迭代。人机对齐的门槛从"能写代码"降到"能读懂意图"，显式控制点确保关键决策不失控
- **供机执行——双态验证、探索提交分离、自适应修复** ：HopJIT 将代码骨干与智能节点双态融合执行，核验内置，确保 LLM 执行正确可靠。**探索提交分离**（act/commit）将不可逆副作用隔离到显式 commit 节点，act 步骤可安全重做——异常时自适应修复，无需人工重编程即可适应变化
- **供业务演进——自主探索、放心尝试、渐进固化** ：业务逻辑从硬编码走向结构化编排，从程序员独占走向业务方可参与。新场景下只需给出目标和约束，探索提交分离确保探索过程无不可逆后果——agent 自主规划探索路径，并在 HopSpec 框架下放心尝试、安全重试，成功经验**渐进固化**为可复用的最佳实践——系统越用越聪明

## 核心创新

**锁定目标，守住边界，放开路径**——WHAT（目标、约束、交付）不可变，HOW（步骤、策略）在契约边界内可自适应。边界由结构化逻辑控制、探索提交分离、双态验证等机制守住。

语言级别把 WHAT（目标、约束、交付）和 HOW（步骤、策略）分离——WHAT 不可变，HOW 在契约边界内可自适应。

### 与传统编程的本质区别

**主逻辑是对齐或验证过的，异常处理是自治的，新逻辑是可以动态演进的。**

- 主路径和人对齐或经人验证，确保做对的事
- 异常路径委托给 LLM 在契约边界内自适应修复，不需要预编码每种故障
- 面对新场景，通过 CITL 交互探索出的有效路径可沉淀为新的 HopSpec，逻辑体系持续演进

### CITL（Caller In The Loop）

从 HITL（Human In The Loop）扩展而来。传统 HITL 只有人类在回路中；HopSpec 的调用链上，每一层 caller 都可能是拥有更广上下文的智能体或人类。失败逐层上报时，每层 caller 都能基于自己的知识范围尝试修复——从当前 subtask 的 adaptive 自愈，到上层 agent 的跨上下文修复，到人类的终极决策。CITL 让回路中的智力不是单点的，而是分层递增的。`confirm` 步骤是显式的 CITL 介入点——不通过时人类可选择放弃、重试或附反馈改进，决策权始终在回路中。

## 三个核心能力

- **可控** — 契约边界锁死 WHAT（Constraints 不可违反、check 不可跳过、Outputs 不可降级），祖先链让每一步都看到自己的 WHAT，防止推理跑偏
- **可靠** — 韧性可自愈。None 传播强制暴露失败（fail 时 HopJIT 自动记录失败原因），adaptive 在契约内推理修复，CITL 逐层上报让更广上下文的调用者介入。`parallel` 内 child fail 时其余 children 继续执行，失败 child 输出为 `None`，由后继步骤决定是否可接受部分结果。提示词构建工程化（5 层上下文组装、祖先链作用域收窄），让主路径的 LLM 执行本身可控可靠
- **可成长** — 面对新场景，通过与 CITL 交互对齐，LLM 探索出的有效路径可以沉淀为新的 HopSpec，成为可复用的最佳实践。系统的智力不只依赖模型能力，还随经验积累而成长

## 语言机制与核心创新的关系

| 机制 | 作用 |
|------|------|
| None 传播 | 让失败不可忽略，逼到契约边界 |
| adaptive | 在 HOW 层面释放 LLM 的推理修复能力 |
| 完整性约束 | 在 WHAT 层面锁死目标不漂移 |
| 祖先链 | 每一步都能看到自己的 WHAT，防止推理跑偏 |
| 探索提交分离（act/commit） | act 步骤可安全重做，不可逆副作用隔离到 commit 节点，沙箱四维度约束执行范围 |
| CITL 分层上报 | 从 adaptive 自愈到 caller 修复到人类决策，推理能力逐层递增 |

## 与传统编程的能力边界对比

传统程序的能力上限是程序员的预见力和编码量。HopSpec 的能力上限是 LLM 的推理力 + CITL 的知识广度 + 沉淀的最佳实践——可控不失灵活，可靠不靠穷举，可成长不靠重写。

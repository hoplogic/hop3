## 文档多语言目录结构【契约】 ^anc-i18n-docs-tree

```
docs/              # 中文 = 源（现位置不动——存量锚点/链接/@trace 零迁移）
docs/i18n/en/      # 英文译本,镜像 docs/ 子树结构（en/concepts/…、en/tutorials/…）
docs/i18n/<lang>/  # 未来语种同款
```

中文在 docs/ 原位作源、译本入 i18n/ 子树——不采用"全语种平级 docs/zh|en/"：迁移存量中文=全库锚点/链接/@trace 大动,收益只有对称美观,代价不成比例。

实施细则（首批实装定形）：
- **目录镜像,文件名本地化**：子树结构镜像 docs/（en/tutorials/…、en/reference/…）,但文件名译为英文 slug（`02-读懂一份spec.md` → `02-reading-a-spec.md`）——译本读者是英文用户,中文文件名对其不可读不可输入;源-译对应关系由译本 @trace 的 source 链接承载,不靠文件名同名;
- **根级文件例外**：README.md 不在 docs/ 下,译本置 `docs/i18n/en/README.md`（镜像树唯一根级例外,不在库根放 README.en.md——库根保持单一中文入口）;
- **链接规则**：译本互链指向译本兄弟（en/ 树内闭环）;链到未翻译文档（design/concepts）时指回中文原文（不留死链,读者可见语言边界）。**死链机检在滞后守卫内**（markdown+wiki 双式全核;**代码位不是链接面**——围栏块与行内反引号内的 `[[...]]`/`](...)` 是示意字面,剥离后再扫,实撞:D1 的 `[[双链]]` 示意 token 译作 `[[wiki-links]]` 被误报）;
- **引用库内真实文件的代码块原样保留**（如 `cat examples/coffee-week.md` 的输出引文——引文忠实于文件实际内容,周边讲解译英文）。

## 翻译三纪律【契约】 ^anc-i18n-translation-discipline

1. **翻译即派生**：每个译本文件带 `@trace type: translation, source: [[中文原文]]`——concepts"受控快照"模式的第三种 type。一致性方向恒为**译本对齐中文源**,不反向（中文改定→译本重刷,译本发现源错误→报修源不自行改译）；
2. **锚点不翻译**：`^anc-*` 在译本保持原名（锚是 ID 不是文案）——跨语言收链可用,TRACEABILITY 不分语言；
3. **滞后可机检**：译本 `last_sync` vs 中文源 git 最后改动日期——复用 last_sync 守卫判据（^anc-driver-lint-last-sync 同款）;初期降档为报告不拦,译本量上来后再议升红。

## 翻译范围分层【决策：作者认可的第一批清单】

- **第一批（用户+开发者面）**：README / tutorials 00-09 **+ D0-D6 生态开发者系列**（2026-08-15 作者纠偏——首版清单漏列 D 系列致范围空白被窄口径执行:教程目录两系列一体,开发者是生态扩张的同级受众,tutorials 整目录入批不再按系列切）/ reference；**primer 移出文档批**——primer 是 skill 构建的运行资产非阅读文档,英文 primer 的消费路径（构建 skill 时按目标语言选 primer）是引擎特性,无该特性则译本是死资产,随'skill 语言化'另立项;
- **第二批（spec 作者面）**：concepts 的 HopSpec 核心规范 + 语法参考；
- **不翻**：docs/design/ 与工程链文档（维护者与 agent 内部面,翻译是纯负债）;TODO/TRACEABILITY 等工作账。

## 关键词双语实施【契约】 ^anc-i18n-keyword-impl

概念权威 ^anc-i18n-keywords-bilingual（方案 B:直通等价/零声明/AST 恒英文规范形/序列化归一/内置函数不翻）。实施分解：

- **parser 入口归一**：三张关键词表（SECTION_KEYWORDS 段头 / 步骤类型表 / 属性与子句表）各加中文别名列——查表命中即映射英文规范形入 AST,parser 之后全链零感知;
- **覆盖面清单**（实装时逐面核,漏一面=中文 spec 该面静默失效）：段头 8/步骤类型 15/属性子句（retry/max/adaptive/final/escalatable/free/for-each…in/collect…into/require_human）/类型名 10+复合形态/特殊值（Null 已三写,else 中文别名=其他）/**名位正则族**（RE_VAR_DECL/Types 段类型名与字段名/Id 签名函数名——所有 `\w+` 名位随变量名 Unicode 条款同宽,漏一处=中文名该形态静默丢,实撞:Types 段 `- 画像:` 整块丢弃）;
  - **平衡扫描入口是独立面**：`[case(条件)]`/`[call id(映射)]` 不走 RE_STEP 常规路而走括号平衡扫描特判,其入口正则与属性尾巴字符集须同步收中文（`[条件(...)]`/`[调用 id(...)]`/尾巴`重试=2 并行`）——只改三表会让这两形态的中文写法静默吞行（实撞:`[情形(其余)]`〔时名〕首版整行不入树）;
- **归一纪律（命名忠实推论,review 实撞两例）**：
  - ①关键词归一必须**词元级**（整 token 精确匹配）,禁子串级替换——变量名含关键词字串（`重试次数`/`并行度`）不得被改写（实撞:子串 split/join 把 case 条件里的 `重试次数` 腐蚀成 `retry次数`、for-each itemVar `并行度` 腐蚀成 `parallel度`——声明与引用从此对不上,静默断链）;
  - ②**内部通道不归一**：`__cond` 条件与 `__callmap` 映射是表达式/变量名面,按作者字面原样保留（条件里没有可翻译的关键词——else/其他 在 buildStep 统配位单独判,不在此归一）;归一动作必须排在内部通道早退**之后**;

**能力契约（HopTrait）**:

```
trait: SpecKeywordConvertSurface
  Id: spec-keyword-convert-surface
  Constraints:
  - 围栏内的行一律不动（``` 开栏到闭栏之间,含开闭栏行本身）
  - 段头行:行首 1-6 个 # 加空白、之后只有一个词到行尾;词转小写后查段头关键词表（八个英文键加八个中文键）命中才转,输出目标语言的规范形（中文表形,或英文首字母大写形）;查不中的标题（如 `## 任务`、`## 背景`）不动
  - Id 行:行首 `Id` 或 `标识` 加冒号,只在第一个段头行之前才转——叙事节里的 `Id:` 字样不误伤
  - 工具授权行:行首可有空白、带 `- ` 前缀的 tools/工具/deny_tools/禁工具 条目,半角或全角冒号都认
  - 裸键段头行（新增）,同时满足以下五条才转,否则不动:
    ① 段区已开启——前面已出现过一级标题行（`# ` 开头,不论后面几个词,如 `# Spec: X`）、关键字二级段头行或 Id 行之一（parser 在此之前不看内联标签）;Id 行不论在第一个段头之前还是之后都开启段区——转不转 Id 行本身是另一回事
    ② 还没进入步骤段——前面没有出现过步骤段的段头（`## Steps`/`## 步骤`,或裸键 `Steps:`/`步骤:`）;步骤段之后的叙事节里出现 `Goal:` 字样不动。这一条比 parser 窄:parser 在步骤段之后遇到首次出现的关键字裸键仍会另起一段,把步骤段截断——那是写错不是合法写法,转换器不跟
    ③ 行形态——行首无空白、无 `- `,键名是一个词,后跟可选空白与半角冒号;全角冒号 `：` 不认（parser 不认）
    ④ 键名转小写后查段头关键词表命中
    ⑤ 这个段种类是第一次出现——关键字二级段头与裸键两种形态共用一份"已出现"记录;同种类第二次出现的行不动（parser 同类段只认第一次,不论形态）
    命中后只替换键名那一段,输出目标语言规范形,冒号及其后原样保留;裸键 `Steps:`/`步骤:` 本身照转,转完即进入步骤段
  - 步骤行（扩面）:行首可有空白、可有任意个 # 加空白（# 的个数不限,与 parser 剥前缀的规则一致）,然后是步骤编号、可选的尾点、空白、左方括号;方括号内交括号内容转换（括号组表达式不动、唯 (else)/(其他) 整组转换——既有规则不变）
  - 词表单一事实源:段种类查段头关键词表,出词查规范形英文表与中文表,三者同源,不另抄第二份
  - 其余一切行不动
```

**关键逻辑（HopSop）**:

```
convertSpecKeywords(text, to) → text:
状态:inFence=false;seenHeading=false（见过任一段头行,管 Id 行）;sectionsOpen=false（段区已开启,管裸键）;
     stepsStarted=false（已进入步骤段）;seenKinds=空集（已出现的段种类）
逐行 line:
1. 行是围栏开闭栏 → 翻转 inFence,原样输出;inFence 为真 → 原样输出
1a. 行是一级标题（`# ` 加任意文字）→ sectionsOpen=true（只置标志,不决定输出,继续往下判）
1b. 行是 Id 行（Id 或 标识 + 冒号 + 非空值）→ sectionsOpen=true（只置标志,继续往下判）
2. 段头行（# 加空白加一个词到行尾）:
   2.1 seenHeading=true
   2.2 kind = 段头关键词表[词转小写];kind 为空 → 原样输出
   2.3 深度 2 → sectionsOpen=true;seenKinds 加 kind;kind 是 steps → stepsStarted=true
   2.4 输出 # 前缀 + 规范形(kind, to) + 行尾空白
3. seenHeading 为假且是 Id 行 → 输出 Id 或 标识 + 原冒号段 + 原值
4. 工具授权行 → 只换条目键名,输出
5. sectionsOpen 为真、stepsStarted 为假、且匹配裸键形态（行首一个词 + 可选空白 + 半角冒号）:
   5.1 kind = 段头关键词表[键名转小写];kind 为空 → 落到第 6 步
   5.2 kind 已在 seenKinds → 原样输出
   5.3 seenKinds 加 kind;kind 是 steps → stepsStarted=true
   5.4 输出 规范形(kind, to) + 冒号起的原文
6. 步骤行（可选空白 + 可选若干 # 加空白 + 编号 + 可选尾点 + 空白 + [内容]）→ 方括号内交括号内容转换,输出
7. 其余原样输出
```

拍板沿革逐条：

- break/continue 中文词第四轮改定（2026-08-15 作者:'break 跳出循环,continue 继续循环'——裸动词『跳出/继续』在步骤摘要散文里常用度过高,全称带宾语自解释）；
- 子句形态（作者两轮裁定,2026-08-15）：`for-each X in L` = `遍历 X 于 L`（首案『逐个』作者否——散文常用词作关键词奇怪;次案『轮询』撞 polling 术语语义,终裁『遍历』——Python/JS 中文社区 for-each 通译零歧义）；`collect U into O` = `收集 U 入 O`；`require_human` = `必须真人确认`；
- 类型名（line/text/…）与 hop_python 内置函数**不翻**（类型词短英文即术语,函数对齐 Python）；`Null`/`else` 已有宽容面维持;else 统配位中文别名 `其他`（`[条件(其他)]` ≡ `[case(else)]`,归一 default,居末规则同享;其他 同入保留字族）；
- on fail 中文词（2026-08-21 作者定:'失败兜底'——比裸'兜底'自释义,兜的是什么一眼明确;行文简称兜底步/兜底块;`[失败兜底]` ≡ `[on fail]`,同入保留字族）；
- escalatable 中文词（2026-08-26 作者定:'可上升'——check 升层声明属性,`[check final 可上升]` ≡ `[check final escalatable]`,同入保留字族;概念权威 [[../concepts/HopSpec V3核心规范#^anc-step-check-escalatable]],review 批闭环:核心规范保留字条此前引用术语表而表中缺席的互指矛盾自此闭合）；
- free 中文词（2026-08-26 作者定:'开放'——free 家族修饰,两宿主:`[探索 开放]` ≡ `[act free]`〔执行自由〕/`[子任务 开放]` ≡ `[subtask free]`〔规划自由,2026-08-27 到步展开批〕,同入保留字族;概念权威 [[../concepts/HopSpec V3核心规范#^anc-step-act]] free 条款;修饰词族此前唯 free 缺中文词——validate 督促无 body 的 act 标 free,常用度高于同批 escalatable,缺口随 escalatable 表行补录同批闭合）；
- case 中文词第五轮改定（2026-08-15 作者:'HopSop里是[条件()]…这两个应该统一''我们的用法更像条件,因为都是各种判断式'——首版『情形』与 HopSop 2026-08-09 先例（`[条件(…)]`+兜底`[条件(其他)]`,其英文对照表本就写 `↔ [case(条件)]`）失察撞车;统配别名 `其余`→`其他` 同批随 HopSop 对齐,两处不一致同根）。

## 关键词保留字闸【契约】 ^anc-i18n-keyword-reserved

**全部语言关键词（中英两表）升变量名保留字**（2026-08-15 作者定"注意关键词都是保留字"）——现状英文关键词未保留（实测 `+ → reason`/`+ → goal` 全绿）,变量与关键词在 `[…]` 机器面/段头位之外虽无直接歧义,但 case 条件裸字消歧、报错文案引用、未来语法位扩展都会撞。

- 实施＝V2 保留字族第四件（else/enum 成员/类型名/**关键词族**）,typeReservedError 同模式共享判据、**检查位与类型名闸恒同位**（else/其他 统配词 2026-08-25 同收编本闸,四族同六位）;
- 六位:Inputs 声明/产出注册/for-each itemVar/collect unitVar/call 输入·输出映射目标——首版只挂前两位,review 全谱对表抓漏后四位,教训与规则 27 的'后三位 review 补漏'完全同构:凡新增变量引入位保留字闸,以 typeReservedError 调用点清单为准逐位成对;
- 存量扫描零命中（examples/scripts/driver）,零破坏落地。中文关键词随术语表拍定同批入族;
- **报文自带完整清单（0029,2026-08-24）**：V2 保留字报文不止点名撞到的词——关键词闸报文附**英文关键词全清单**（从 LANG_KEYWORDS 现生成,单一事实源防清单与实现漂移）＋一句"各词的中文关键词同为保留字"＋指路语法参考「变量与数据流」节;类型名闸报文附类型名全表（同款从 BUILTIN_TYPES 现生成,滤 [line] 列表简写形——首版手写清单即混入不存在的 fragment,漂移实证）＋条件统配词 else/其他 提示＋同款指路;

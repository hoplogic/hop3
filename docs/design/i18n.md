## 文档多语言目录结构【契约】 ^anc-i18n-docs-tree

```
docs/              # 中文 = 源（现位置不动——存量锚点/链接/@trace 零迁移）
docs/i18n/en/      # 英文译本,镜像 docs/ 子树结构（en/concepts/…、en/tutorials/…）
docs/i18n/<lang>/  # 未来语种同款
```

中文在 docs/ 原位作源、译本入 i18n/ 子树——不采用"全语种平级 docs/zh|en/"：迁移存量中文=全库锚点/链接/@trace 大动,收益只有对称美观,代价不成比例。

实施细则（首批实装定形）：
- **目录镜像,文件名本地化**：子树结构镜像 docs/（en/tutorials/…、en/reference/…）,但文件名译为英文 slug（`02-读懂一份spec.md` → `02-reading-a-spec.md`）——译本读者是英文用户,中文文件名对其不可读不可输入;源-译对应关系由译本 @trace 的 source 链接承载,不靠文件名同名;
- **根级文件例外**：README.md 不在 docs/ 下,译本置 `docs/i18n/en/README.md`（镜像树唯一根级例外,不在库根放 README.en.md——库根保持单一中文入口）;
- **链接规则**：译本互链指向译本兄弟（en/ 树内闭环）;链到未翻译文档（design/concepts）时指回中文原文（不留死链,读者可见语言边界）。**死链机检在滞后守卫内**（markdown+wiki 双式全核;**代码位不是链接面**——围栏块与行内反引号内的 `[[...]]`/`](...)` 是示意字面,剥离后再扫,实撞:D1 的 `[[双链]]` 示意 token 译作 `[[wiki-links]]` 被误报）;
- **引用库内真实文件的代码块原样保留**（如 `cat examples/coffee-week.md` 的输出引文——引文忠实于文件实际内容,周边讲解译英文）。

## 翻译三纪律【契约】 ^anc-i18n-translation-discipline

1. **翻译即派生**：每个译本文件带 `@trace type: translation, source: [[中文原文]]`——concepts"受控快照"模式的第三种 type。一致性方向恒为**译本对齐中文源**,不反向（中文改定→译本重刷,译本发现源错误→报修源不自行改译）；
2. **锚点不翻译**：`^anc-*` 在译本保持原名（锚是 ID 不是文案）——跨语言收链可用,TRACEABILITY 不分语言；
3. **滞后可机检**：译本 `last_sync` vs 中文源 git 最后改动日期——复用 last_sync 守卫判据（^anc-driver-lint-last-sync 同款）;初期降档为报告不拦,译本量上来后再议升红。

## 翻译范围分层【决策：作者认可的第一批清单】

- **第一批（用户+开发者面）**：README / tutorials 00-09 **+ D0-D6 生态开发者系列**（2026-08-15 作者纠偏——首版清单漏列 D 系列致范围空白被窄口径执行:教程目录两系列一体,开发者是生态扩张的同级受众,tutorials 整目录入批不再按系列切）/ reference；**primer 移出文档批**——primer 是 skill 构建的运行资产非阅读文档,英文 primer 的消费路径（构建 skill 时按目标语言选 primer）是引擎特性,无该特性则译本是死资产,随'skill 语言化'另立项;
- **第二批（spec 作者面）**：concepts 的 HopSpec 核心规范 + 语法参考；
- **不翻**：docs/design/ 与工程链文档（维护者与 agent 内部面,翻译是纯负债）;TODO/TRACEABILITY 等工作账。

## 关键词双语实施【契约】 ^anc-i18n-keyword-impl

概念权威 ^anc-i18n-keywords-bilingual（方案 B:直通等价/零声明/AST 恒英文规范形/序列化归一/内置函数不翻）。实施分解：

- **parser 入口归一**：三张关键词表（SECTION_KEYWORDS 段头 / 步骤类型表 / 属性与子句表）各加中文别名列——查表命中即映射英文规范形入 AST,parser 之后全链零感知;
- **覆盖面清单**（实装时逐面核,漏一面=中文 spec 该面静默失效）：段头 8/步骤类型 15/属性子句（retry/max/adaptive/final/escalatable/free/for-each…in/collect…into/require_human）/类型名 10+复合形态/特殊值（Null 已三写,else 中文别名=其他）/**名位正则族**（RE_VAR_DECL/Types 段类型名与字段名/Id 签名函数名——所有 `\w+` 名位随变量名 Unicode 条款同宽,漏一处=中文名该形态静默丢,实撞:Types 段 `- 画像:` 整块丢弃）。**平衡扫描入口是独立面**：`[case(条件)]`/`[call id(映射)]` 不走 RE_STEP 常规路而走括号平衡扫描特判,其入口正则与属性尾巴字符集须同步收中文（`[条件(...)]`/`[调用 id(...)]`/尾巴`重试=2 并行`）——只改三表会让这两形态的中文写法静默吞行（实撞:`[情形(其余)]`〔时名〕首版整行不入树）;
- **归一纪律（命名忠实推论,review 实撞两例）**：①关键词归一必须**词元级**（整 token 精确匹配）,禁子串级替换——变量名含关键词字串（`重试次数`/`并行度`）不得被改写（实撞:子串 split/join 把 case 条件里的 `重试次数` 腐蚀成 `retry次数`、for-each itemVar `并行度` 腐蚀成 `parallel度`——声明与引用从此对不上,静默断链）;②**内部通道不归一**：`__cond` 条件与 `__callmap` 映射是表达式/变量名面,按作者字面原样保留（条件里没有可翻译的关键词——else/其他 在 buildStep 统配位单独判,不在此归一）;归一动作必须排在内部通道早退**之后**;
- **serializer——按 language 配置出目标语言** ^anc-i18n-serialize-lang：（2026-09-09 review 面四抓锚真身缺席后补立——本锚 2026-09-03 起被 src/tools.ts 等处 @a: 引用但设计侧从未立真身,五层链设计环断,audit orphans 在列;锚义=本条:序列化/读回/生成面/配置合并与打底的 language 特性实现总锚,0084 M2/M4 的合并与打底新挂点同归此锚）（2026-09-03 作者拍板升格——原 v1'恒英文规范形+中文写回撞到再升'的后续条款,本日真需求到:hopbuild 生成物要缺省中文关键词。作者两拍:序列化跟随 language 配置〔否掉'跟随原文检测'与'恒英文只教学'两案〕+配套转换工具〔备份后原地改写〕）。serializeSpec/serializeFragment 加可选 lang 参数（缺省 'en'=既有行为逐字节不变,零破坏）;lang='zh' 时关键词位按 ^anc-i18n-glossary 术语表写中文（段头/Id 行/步骤类型/属性子句/for-each·collect 子句/case(else)→条件(其他)/on fail→失败兜底）;**反向映射表由正向别名表程序化反转生成,单一事实源禁手抄第二份**（两份表必漂移）;AST 恒英文规范形不动——语言只活在文本面;
- **language 配置键** ^anc-i18n-language-config：【契约,2026-09-03】项目级 hopjit.yaml `language: zh|en`,缺省 en;读取形态照 readProjectCommands 单键读（文件缺席/坏 YAML/坏值一律回 en 安全侧）,入 HostConfig.language;系统级不设——生成物语言是项目属性。三个消费面:①序列化（上条）;②hopbuild2 生成物（引擎把 language 注入 hop_env 表 `hop_env_language` 键——既有 hop_env 通道零新机制,拼文件头 body 按它选段头语言,教学面告知分拆 LLM 用中文关键词写骨架;双语直通下英文骨架也合法,机械面不拦语言只有转换工具归一）;③转换工具（下条）;
- **关键词转换工具**【契约,2026-09-03 作者拍'做一个工具,备份后直接 in-place 改写'】：CLI 子命令 `hopjit lang <spec> --to zh|en`（命名 2026-09-03 作者两轮:首名 i18n-convert 被抓'太复杂',改 lang——与配置键 language 同词根,最短零歧义）——①备份 `<原名>.bak.<时间戳>` 同目录（已存在加序号不覆盖）;②**行级手术**改写（只替换关键词 token 所在行的关键词部分,变量名/说明文字/body/叙事节字节不动——serializeSpec 单向有损〔丢 %% 块/HTML 注释锚/续行注释〕禁用于整文重建,与树编辑工具 ^anc-exec-tree-edit-line-surgery 同哲学）;③映射表与 serializer 反向表同源（import 同一常量）;④写回前内存中对转换产物 validate 与原件对照,errors 数不一致即拒绝写回退出非 0——原件未动、备份不产生（转换不引病;比'先写后回滚'更安全:拒绝路径零盘面变化）;⑤双向可逆:en→zh→en 逐字节一致（词元级替换的可逆性由词表一一对应保证）;
- **报错文案**：报文中的关键词引用按输入形态回显（作者写中文报中文——报错指向作者写的字面,不指规范形）;
- **实装前置**：中文术语表已拍定（2026-08-15 作者三轮裁定,act 两候选'尝试/试算'后定'探索'——与教程 03'探索与提交'主线词一致）。

**中文术语表【权威】** ^anc-i18n-glossary：

| 英文 | 中文 | 英文 | 中文 | 英文 | 中文 |
|---|---|---|---|---|---|
| Id | 标识 | reason | 推理 | branch | 分支 |
| Goal | 目标 | act | **探索** | case | 条件 |
| Constraints | 约束 | check | 检查 | subtask | 子任务 |
| Types | 类型 | confirm | 确认 | loop | 循环 |
| Inputs | 输入 | ask | 询问 | parallel | 并行 |
| Outputs | 输出 | commit | 提交 | break | 跳出循环 |
| Config | 配置 | call | 调用 | continue | 继续循环 |
| Steps | 步骤 | exit | 结束 | retry | 重试 |
| max | 上限 | adaptive | 自适应 | final | 终检 |
| on fail | **失败兜底** | escalatable | 可上升 | free | **开放** |
| tools | 工具 | deny_tools | 禁工具 | | |

break/continue 中文词第四轮改定（2026-08-15 作者:'break 跳出循环,continue 继续循环'——裸动词『跳出/继续』在步骤摘要散文里常用度过高,全称带宾语自解释）。子句形态（作者两轮裁定,2026-08-15）：`for-each X in L` = `遍历 X 于 L`（首案『逐个』作者否——散文常用词作关键词奇怪;次案『轮询』撞 polling 术语语义,终裁『遍历』——Python/JS 中文社区 for-each 通译零歧义）；`collect U into O` = `收集 U 入 O`；`require_human` = `必须真人确认`。类型名（line/text/…）与 hop_python 内置函数**不翻**（类型词短英文即术语,函数对齐 Python）；`Null`/`else` 已有宽容面维持;else 统配位中文别名 `其他`（`[条件(其他)]` ≡ `[case(else)]`,归一 default,居末规则同享;其他 同入保留字族）。on fail 中文词（2026-08-21 作者定:'失败兜底'——比裸'兜底'自释义,兜的是什么一眼明确;行文简称兜底步/兜底块;`[失败兜底]` ≡ `[on fail]`,同入保留字族）。escalatable 中文词（2026-08-26 作者定:'可上升'——check 升层声明属性,`[check final 可上升]` ≡ `[check final escalatable]`,同入保留字族;概念权威 [[../concepts/HopSpec V3核心规范#^anc-step-check-escalatable]],review 批闭环:核心规范保留字条此前引用术语表而表中缺席的互指矛盾自此闭合）。free 中文词（2026-08-26 作者定:'开放'——free 家族修饰,两宿主:`[探索 开放]` ≡ `[act free]`〔执行自由〕/`[子任务 开放]` ≡ `[subtask free]`〔规划自由,2026-08-27 到步展开批〕,同入保留字族;概念权威 [[../concepts/HopSpec V3核心规范#^anc-step-act]] free 条款;修饰词族此前唯 free 缺中文词——validate 督促无 body 的 act 标 free,常用度高于同批 escalatable,缺口随 escalatable 表行补录同批闭合）。case 中文词第五轮改定（2026-08-15 作者:'HopSop里是[条件()]…这两个应该统一''我们的用法更像条件,因为都是各种判断式'——首版『情形』与 HopSop 2026-08-09 先例（`[条件(…)]`+兜底`[条件(其他)]`,其英文对照表本就写 `↔ [case(条件)]`）失察撞车;统配别名 `其余`→`其他` 同批随 HopSop 对齐,两处不一致同根）。

## 关键词保留字闸【契约】 ^anc-i18n-keyword-reserved

**全部语言关键词（中英两表）升变量名保留字**（2026-08-15 作者定"注意关键词都是保留字"）——现状英文关键词未保留（实测 `+ → reason`/`+ → goal` 全绿）,变量与关键词在 `[…]` 机器面/段头位之外虽无直接歧义,但 case 条件裸字消歧、报错文案引用、未来语法位扩展都会撞。实施＝V2 保留字族第四件（else/enum 成员/类型名/**关键词族**）,typeReservedError 同模式共享判据、**检查位与类型名闸恒同位**（else/其他 统配词 2026-08-25 同收编本闸,四族同六位）（六位:Inputs 声明/产出注册/for-each itemVar/collect unitVar/call 输入·输出映射目标——首版只挂前两位,review 全谱对表抓漏后四位,教训与规则 27 的'后三位 review 补漏'完全同构:凡新增变量引入位保留字闸,以 typeReservedError 调用点清单为准逐位成对）;存量扫描零命中（examples/scripts/driver）,零破坏落地。中文关键词随术语表拍定同批入族。**报文自带完整清单（0029,2026-08-24）**：V2 保留字报文不止点名撞到的词——关键词闸报文附**英文关键词全清单**（从 LANG_KEYWORDS 现生成,单一事实源防清单与实现漂移）＋一句"各词的中文关键词同为保留字"＋指路语法参考「变量与数据流」节;类型名闸报文附类型名全表（同款从 BUILTIN_TYPES 现生成,滤 [line] 列表简写形——首版手写清单即混入不存在的 fragment,漂移实证）＋条件统配词 else/其他 提示＋同款指路。动机:作者用 `outputs`/`steps` 等自然变量名撞闸后只知当前词,无先验避用每撞一次改一次名——报文一次给全清单,文档面（语法参考+hopbuild-primer）同步列表,双面供给。

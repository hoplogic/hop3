# 教程 3 · 探索与提交：放心尝试的机制

**目标**：理解 `act` 和 `commit` 的分界，学会写"可以随便重试的探索"和"必须一锤定音的提交"，知道执行过程中的临时文件该放哪。
**前提**：完成 [[02-读懂一份spec]]（认识 act/commit/confirm 这些类型名即可）。

## 一个问题引出全部：失败了敢不敢重来？

LLM 执行任务会失败，失败了最好的办法是重试。但有些事**重试是灾难**：邮件发两遍、订单提交两次、生产文件覆盖两回。自然语言 skill 里这靠 LLM 自己掂量"这步危险"，掂量错一次就出事故。

HopSpec 的答案是把"敢不敢重来"写进步骤类型——**探索提交分离**：

|         | `act`（探索）                                  | `commit`（提交）                                           |
| ------- | ------------------------------------------ | ------------------------------------------------------ |
| 副作用     | **必须可逆**：纯计算、查询、沙箱/临时区读写                   | **不可逆**：发邮件、支付、写生产库、改正式文件                              |
| 失败了     | 引擎放心重试（retry/adaptive 随便重跑）                | **不准裸放进 retry 容器**（前面有 `check final` 或 `confirm` 把关才行） |
| 授权      | 不需要                                        | 自身不带授权——**能跑到 commit 说明把关已在前面完成**                      |
| body 文法 | 同一套 hop_python（下一篇 [[D10-hop_python计算体]] 讲） | 完全同源，唯一区别就是上面三行                                        |

这个分界带来的自由是：**act 步骤里 agent 可以放开手脚探索**——试算、起草、多试几版，失败重来零成本；所有不可逆后果被隔离在显式的 `commit` 节点，而 commit 前面必然站着一道闸。

## 第 1 步：跑一个完整的探索→把关→提交链

Claude Code 命令：

```
/hopspec run examples/syntax/confirm-commit.md
```

Codex 命令：

```
$hopspec run examples/syntax/confirm-commit.md
```

这个 spec 做批量重命名，七步走完一条教科书式的链：

```
1   [act]     扫描文件列表          ← 探索：读操作，随便重来
2   [reason]  生成重命名方案        ← 推理：设计方案
3   [confirm] 用户确认方案          ← 把关：引擎强制停下等你
4   [act]     生成可逆备份          ← 探索：备份是可逆准备动作
5   [loop]    逐项执行重命名        ← 批量不可逆的正形：loop 里放 commit
5.1 [commit]  重命名单项（不可逆）  ← 提交：到这里才动真格，每项一发、各自幂等
6   [act]     汇总重命名计数
7   [reason]  生成报告
```

跑到第 3 步它**必定**停下问你——批准了才有第 5 步。你拒绝的话：全局中止，所有未执行步骤标 `skipped`，**commit 绝不执行**。这不是礼貌，是 `confirm` 的语义。

## 第 2 步：写 commit 的三条规矩

**规矩一：前面必须有闸。** 需要人拍板的放 `confirm`（教程里的形态）；能机检的放 `check`。没有任何把关的 commit 过不了心智审查——"能执行到 commit 说明授权已完成"是它的语义前提。

**规矩二：commit 必带 hop_python body（引擎强制）。** 不可逆动作必须在写卡时用代码定死——执行期零裁量，动什么、怎么动，全在写 spec 时就白纸黑字确定，不留给执行 LLM 现场发挥的空间。没有代码块的 commit 引擎拒载。body 本身还要设计成"重放无害"的幂等形态——引擎侧虽有一道硬保险（见规矩三的"退火"），但崩溃恢复仍可能重放 commit。看样例第 5.1 步的写法：

````markdown
5.1. [commit] 重命名单项（不可逆）
  - ← item, target_dir
  + → moved_flag: int  # 1=真移动 0=跳过
  > 幂等设计：目标名已存在且源文件已不在则视为本项已完成、跳过——避免崩溃重放时重复重命名或报错。
  > ```hop_python
  > src = target_dir + "/" + item.old
  > dst = target_dir + "/" + item.new
  > src_probe = parse_json(exists(path: src))
  > dst_probe = parse_json(exists(path: dst))
  > done_already = dst_probe.exists and not src_probe.exists
  > moved = "" if done_already else move(from: src, to: dst)
  > moved_flag = 0 if done_already else 1
  > ```
````

先查再做（目标态已达成就跳过，upsert 而非盲 insert），是最常用的幂等手法。

**规矩三：别裸放进 retry 容器。** `[subtask retry=N]` 里的步骤会被整体重跑——commit 裸放在里面就意味着不可逆动作可能执行 N 次。例外是它前面站着把关步（`check final` 或 `confirm`）：重跑会先过闸，闸不放行 commit 就不会重复执行。validator 按这个判据拦（裸 commit 报错，有前置把关放行），但先懂为什么。

**引擎还有一道兜底：commit 成功后事务"退火"。** 一个 commit 真的执行成功之后，它所有的祖先容器**自动失去 retry 资格**——此后这条链上再有失败，不重跑、直接如实上报。所以不用担心"commit 之后后面某步失败，整组重跑把 commit 再提交一遍"：不可逆动作是事务的单向阀，commit 前是可重试的探索区，commit 后只能向前走或如实失败。这道保险管的是**引擎不制造重放**；崩溃后的恢复重放它管不到——那正是规矩二幂等要补的另一半。

## 第 3 步：work_zone——探索期的自由领地

act 步骤"可以随便写文件"，写到哪？每个执行单元有一块**独占工作区 `work_zone/`**（在 `.hopstate/<实例>/` 下，引擎自动创建），这是探索期临时文件的唯一合法领地：

- **随便写**：草稿、中间结果、试算产物，想写几版写几版——它就是给探索用的；
- **天然隔离**：并行的每个 worker 有自己的 work_zone（目录名带步骤号），互相绝不撞车——你不用为并发考虑文件名冲突；
- **越界即拒**：往 `/tmp` 或项目根写临时文件？引擎在提交时校验路径，越界直接拒绝——这不是刁难，是把"探索不弄脏外面"从自觉变成结构；
- **大数据自动走这**：步骤间传递超过 4KB 的值，引擎自动卸到 `work_zone/vars/` 落盘、传指针——你不用管，知道大文件在那能找到就行。

**心智模型**：work_zone 之内 = 探索区（怎么折腾都行，重试即重来）；work_zone 之外 = 真实世界（要动它，走 commit + 前置把关）。

## 第 4 步：边界由谁守（了解即可）

日常写 spec，你需要的边界就是前面讲过的两道，都由引擎强制：**work_zone 越界校验**（临时文件写出工作区，提交时直接拒）和 **commit 的前置把关规则**（validator 拦裸 commit）。这已经覆盖个人与团队场景的安全需要。

再往上还有一层**沙箱四维度**（`SandboxConfig`：filesystem / network / runtime / database 声明式划定 act 能触及的范围）——这是留给**生产环境部署**的高级议题：多租户、审计合规、精细化资源边界那一档的需求。日常不用配，感兴趣见 `docs/design/sandbox.md`。

## 这就是"放心尝试"的全部机制

回看核心创新那句话——"锁定目标，守住边界，放开路径"：

- **锁定目标**：Goal / Constraints / Outputs 写死交付契约；
- **守住边界**：探索提交分离（本篇）+ 把关闸门（confirm/check）+ work_zone/沙箱；
- **放开路径**：边界之内，agent 自主探索、失败重试、adaptive 重规划——怎么走都出不了事。

新场景敢让 agent 自己试，就是因为试错被结构性地关在了笼子里。

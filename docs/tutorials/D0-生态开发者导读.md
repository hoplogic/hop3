# D0 · 生态开发者导读：项目主线十站

**给谁**：要**参与 HOP 生态开发**的人——读懂概念体系、沿锚点读代码、给引擎/驱动层/工具链做贡献，或深度评估这个项目。**只想用它跑任务/写 spec 的，走用户系列**：[[00-新人导读]] 分流页 → 教程 01-10，不需要读本篇。
**结构**：主线是**十站**，每站回答一个问题、指向一份权威文档。前七站是"懂"（从理念到工程纪律），后三站是"用"（从安装到构建自己的 hopskill——与用户系列共用那几篇）。按顺序走完即建立完整图景。

## 第 1 站 · 工程实现链规范（⚖️ 元规范，精读）

`docs/concepts/工程实现链规范.md`。**先于其余一切文档**——概念→设计→代码→测试四层链、宪法级红线（收链前置/设计先行）、决策 vs 推演的作业协议，全库文档和代码都按它组织。不读它，后面每份文档的分级表、锚点、"契约"字样你都不知道为什么存在。

**读法**：精读全篇。读完自检：能否说出"为什么改 src 前必须先改 design"、"什么是可行域逐层收窄"。

## 第 2 站 · 定位与核心创新（HopSpec 凭什么存在）

先读 `docs/concepts/HopSpec核心创新.md`（短，整体定位——业务逻辑从硬编码走向结构化编排、探索提交分离、渐进固化），再读 `docs/concepts/HopSpec V3核心规范.md` 的 §定位 + §步骤类型 + §执行模型。

**读法**：核心创新通读；核心规范抓住三件事——15 种步骤类型里**谁推理（reason）谁计算（act）谁把关（confirm/check）**、None 传播、人机介入点是语言结构不是运行时礼貌。其余章节当字典回查（它是全库 `^anc-*` 锚点的最大源头）。

## 第 3 站 · 架构语言 HopType（struct/impl/Spec）

`docs/concepts/HopType体系.md`。本项目描述架构不用自由散文，用 **HopType 三件套**：`struct`（组件身份与状态边界）/ `trait`（能力契约）/ `impl`（行为实现，HopSpec 即 impl 的语言）。类比 Rust：struct/trait/impl 的关系一致，只是 impl 可以由 LLM 承担（双态融合）。

**读法**：通读定位与类比两节即可。读完你才能看懂第 4 站 ARCHITECTURE.md 里"用 struct/impl/Spec 体系描述自身架构"、"双态分布"这些表述，以及各设计文档的"HopType 四要素"（定位/关系/traits/impl 逻辑）写法。

## 第 4 站 · 架构（ARCHITECTURE.md）

`ARCHITECTURE.md`。三层结构（引擎核心=纯流控零 I/O 假设 ← 驱动适配 ← 载体）+ 两种模式（复用/独立）是全部架构的骨架。**精读**：架构分层、分层桥接点（已核准的跨层依赖封闭集）、组件交互、双态分布（哪些 struct 是 TS 确定性实现、推理智能在哪一侧）。教学讲述版（按"为什么"重排的全景）见 [[D4-架构讲解]]。

**注意**：ARCHITECTURE 是架构总览，不是模块细节的家——模块清单与每模块的链在第 6 站。

## 第 5 站 · 模块规范（module-principles.md）

`docs/design/module-principles.md`。模块工作的原则权威，五件事：健康模块四判据（锚点+边界声明/@module 归属/可独立收链/专属红灯）、依赖方向三层规则（shared<core<adapter，低层不得引高层）、**接口边界**（出口清单=对外依赖面封闭集，表外即内部）、**版本与兼容**（版本号由出口清单兼容性变化驱动）、拆分触发判据 T1-T5（无信号不拆）。

**读法**：通读。这是你第一次改代码前必须内化的规矩——尤其"说不出消费方的 export 不准出口"和"改 src 前对应模块的设计先改定"。

## 第 6 站 · 模块（Doctree 模块索引 → 逐模块收链）

打开 `Doctree.md`「模块索引」——14 个模块每行一条链：模块锚点 → 概念上游 → 设计权威 → src 文件 → 测试。**这是本项目特有的读码法，不要从 src/ 第一个文件顺着读**：

1. 选一个模块（第一个建议 **doc-ref**，163 行五脏俱全）；
2. 进它的设计文档，先读三件套：**分级表**（注意力配给决策与契约）、**模块版本引块**（边界声明）、**出口表**（对外接口封闭集）；
3. 对每个 `^anc-*` 契约，`grep '@a: anc-xxx' src/` 直达实现行、`grep '@v: anc-xxx' tests/` 直达验证用例——**沿锚点跳，不顺文件读**；
4. `TRACEABILITY.md` 搜同一锚点，核对整条链卡片。

**20 分钟练习**：走通 `anc-exec-doc-ref-resolve` 一条链（设计契约→实现→测试→卡片）。走完即掌握通用读码法。大模块（exec-engine 1900+ 行）同法但只收单条契约链——**引擎不是用来通读的，是按契约查询的**。

## 第 7 站 · 机检守卫与人的职责（chain-enforcement）

`docs/design/chain-enforcement.md`。守卫总图：链的每环由谁守、空白台账（哪些环显式接受不守）、守卫准入规则。**关键认知：三类守卫性质不同，机检只是第一类**——

| 类 | 守什么 | 谁执行 |
|---|---|---|
| 确定性机检 | 锚点格式/层向依赖/模块边界/测试/覆盖率/审计基线 | `npm run check*` + pre-commit hook + CI，**机器全自动** |
| 语义审计 | 设计是否忠实传达概念、实现是否符合契约**意图** | **人/LLM** 跑 anchor-audit skill（里程碑/发版前必跑，G3 节奏） |
| 行为纪律 | 收链前置、决策不越权、默认动手问是例外 | **只能靠人**评审——机器查不了"你动手前有没有收链" |

所以**人要重点查的**是后两类：发版前跑一轮全量语义审计；评审时盯"这个改动收链了吗、该上报的决策上报了吗、v1 偏差标注了吗"。**机检全绿 ≠ 链健康**——这句话在报告尾部固定出现，就是防你把第一类的绿当成全部。

## 第 8 站 · 安装

[[01-第一次运行-ClaudeCode]] 第 1-2 步：`npm i -g @hoplogic/hopjit` + `hopjit install-skill`。速查版在 `USAGE.md` §1-2。**复用模式不需要任何 API key**——这不是省事技巧，是架构决定（推理由外层 LLM 承担，引擎纯流控）。

## 第 9 站 · 使用

[[01-第一次运行-ClaudeCode]] 第 3-6 步：`/demo-coffee-week` 最短首跑（具名 skill 产品形态）→ validate 闸门 → `/hopspec run` 通用驱动 → 体验 ask/confirm 介入点（"停下问你是 spec 作者声明的结构，不是 LLM 的礼貌"）。Codex 载体入口与差异见 [[01-第一次运行-Codex]]。**两种模式的取舍**（复用入门零配置；长任务转独立模式——沙箱独立、可换轻量模型省成本、代价是一次性配置；入口是两个命令：`/hopspec` 恒复用、`/hopspec-mcp` 恒独立,名字即模式,详见 [[D8-模型与工具配置]] 开头）见 `USAGE.md` §6。日常速查 `USAGE.md` §5 命令表。

## 第 10 站 · 构建与优化 hopskill

[[07-升级你的自然语言skill]]：几类稳定复现的事故（漏遍历/跳核验/试错期不可逆/该问人没问）→ `/hopbuild` 翻译 → 作者终审（对 source.md 原文副本核忠实）→ `hopjit pack` 打包成具名 skill。深入优化查 `skills/hopbuild/hopbuild-primer.md`（统一知识源:纪律句翻译判据/步骤类型速查/语法细则）与 `docs/concepts/HopSpec V3语法参考.md`。闭环：**自然语言 skill →（翻译）→ spec →（pack）→ 更可靠的具名 skill**。

## 走完之后：第一次改动

> 开发实操双篇（主线=概念-架构-模块-设计三件套 + AI coding）：[[D1-用AI做工程-从概念到设计]] → [[D2-用AI做工程-AIcoding与验收]]。

两条行为宪法（违反即错）：**收链前置**（第 6 站的方法就是收链）、**设计先行**（改 src 前对应 design 先改定）。节奏：`ls todo/` 挑小项（文件名即状态,open 卡即可动手）→ 改设计 → 改代码（`@a:`）→ 补测试（`@v:`）→ TRACEABILITY 立卡 → `npm run check`。改动涉及 driver/引擎想在本机 CC 里试：`npm run dev:install`（重建 dist+装最新 skill，成对刷新）；发版走 `npm run release`（十步检查单）。**npm run 必须在本仓库根目录执行**（读当前目录 package.json，在别处跑报 ENOENT——直接调 `<仓库>/scripts/dev-install.sh` 则任意目录可用，脚本自 cd）。机检红了不是麻烦，是它在替你挡返工。**新建模块**是收链把关最重的一档——agent 按模块八件单（`chain-enforcement.md` §1c-2）一次改动交齐（人只核交没交齐）。成为例行维护者之后，提交/发版的每次操作清单见维护者操作手册（内部维护面,不随快照分发；手册层：每次都用，不用回头翻本教程）。

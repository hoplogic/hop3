# 10 · 钉钉通知：任务跑完了，手机上知道

**给谁**：把长活交给引擎后不想守着终端的人——跑完了、失败了、停下来等你确认了，钉钉推一条到手机。
**前置**：教程 04（日常活交给 hop）。不需要写任何代码。

## 一句话定位

**配好一次凭证，之后每次开活时带一句**：把活交给 /hop 时说"**跑完钉钉通知我**"，这个活到终态（完成/失败）或停下等你确认时，钉钉就会收到一张状态卡片。推送是引擎的活——**你全程不需要敲任何命令**；这一次没说，这一次就什么都不会发。

## 一次性准备（约五分钟）

**第一步：建一个钉钉机器人。**

1. 在钉钉建一个群。想只发给自己：建群时随便拉一个人，建完把对方移出去——只剩你一人的群，消息等同发给你个人，手机照常推送；
2. 群设置 → 机器人 → 添加机器人 → **自定义机器人**；
3. 安全设置选**加签**（推荐——三个选项里防护最实在的一档），记下 `SEC` 开头的密钥；
4. 完成后复制 webhook 地址（`https://oapi.dingtalk.com/robot/send?access_token=...`）。

**第二步：把凭证放进环境变量。**

在 `~/.zshrc`（或你的 shell 配置文件）里加两行：

```bash
export DINGTALK_WEBHOOK='https://oapi.dingtalk.com/robot/send?access_token=你的token'
export DINGTALK_SECRET='SEC你的密钥'   # 加签模式才需要;选了关键词档就不用这行
```

> ⚠️ 凭证只放环境变量，**不要写进任何会提交到 git 的文件**。webhook 泄露的后果是别人能往你群里发消息（发不了别的、也读不到任何东西），撤销机器人重建即止损——但没必要给自己找事。
> 粘贴时留意别把多余字符带进去（首跑实撞：webhook 尾部粘了下一行的开头，钉钉报 `token is not exist`）。

**第三步：测一下。**

重开一个终端（让环境变量生效），进 Claude Code 或 Codex，交一个最小的活并要通知：

> /hop 随便算个 3+5，跑完钉钉通知我

手机收到 ✅ 卡片就绪。没响就看 agent 转告的报错——最常见的三种：webhook 粘贴时带了多余字符（钉钉报 `token is not exist`）、加签密钥不对、关键词档消息里没带设定的词。

## 配好之后长什么样

你说"**/hop 把这批数据整理成周报，跑完钉钉通知我**"，然后去开会。三种时刻手机会响：

- **跑完了**——✅ 卡片，带任务名与进度：

  > ### ✅ 完成 数据周报整理
  > - 进度: 6/6 步
  > - 实例: 20260831-1a2b3c

- **跑失败了**——❌ 卡片，带失败在哪一步、为什么；
- **停下等你了**——⏸️ 卡片，带停点问题。计划里有要你拍板的步骤（确认口径、审批发送）而你不在场时，这条最值钱：不通知的话任务就静默挂着，你回来才发现它白等了半天。回来对 agent 说"继续"就续上。

三条规则，避免误会：

- **点名渠道才推手机**。"跑完钉钉通知我""钉我一下"都算数；光说"跑完通知我"不算——那是让 agent 在对话里回话，不是推手机。没说就完全不发——引擎不替你决定要不要打扰你，环境变量配着也不会擅自发；
- **一次一说，跟着活走**。通知意愿属于这一个活：开活时说一句，管这个活的全程（中断续跑后照样有效），不用每一步重复。下一个活想要通知就再说一句。**没有全局开关、没有配置文件**——不会出现"忘了关，每个活都在轰炸手机"；
- **通知失败不影响干活**。凭证没配、网络不通，任务照常跑完，agent 会转告你一句没发出去的原因。

## 想调整通知内容？对话里说

卡片的正文归引擎渲染，个性化的加料对话里提就行，例如：

- "重要的活停下等我时，通知里 @我一下"（消息会在钉钉里标红——agent 会把手机号带给发送口）；
- "通知里带上一句'记得复核第 3 步'"。

## 边界与提醒

- **只发不收**：这是纯发送口。在钉钉群里 @机器人 说话它听不见——"从钉钉发命令驱动引擎"是另一套机制（企业应用+长连接），尚未提供；
- **限流**：钉钉群机器人每分钟最多 20 条——正常通知场景碰不到，别放进循环里刷；
- **消息内容别带敏感信息**：webhook 消息走钉钉服务器，凭证、内网路径这类内容不要写进正文；
- 换群/换机器人 = 换 `DINGTALK_WEBHOOK` 环境变量，其余不动；
- **MCP 独立模式**（注册了 hopjit MCP server 的场景）同样支持：对 agent 说法不变，底层走 server 的通知挂点——该形态下项目 config 里要声明一次通道（`notify: {channel: dingtalk}`），agent 会在你首次要通知时提示。

# D3 · 两本账：todo/ 与 hopissues 的使用

> 〔内部开发面〕本篇教的双账工作流（todo/ 事项卡+hopissues 跨项目通道）目前只在维护者内网工作区运转，GitHub 公开快照暂不含这两个目录——外部读者可当方法论参考读，实操通道后继开放。

**给谁**：要在本库干活的开发者（人或 agent）——你迟早会撞见一件"现在修不了/不归我修/要别人配合修"的事，它该记在哪、怎么记、怎么闭环，这篇讲清。
**前置**：[[D0-生态开发者导读]]。

## 一句话分工

**本库自己的事记 `todo/`，跨项目的事走 `../hopissues/`**——判据就一条：这件事的修复方是谁。自己修=todo/ 立卡；要报给别人修、或别人报来要我们修=hopissues 立卡。不存在第三个去处（"直接写对方库的 TODO"是被废除的越权形态）。

两处的规则权威都不在本篇：`todo/README.md` 是库内卡的差异权威，`../hopissues/README.md` 是跨项目通道的唯一权威。**本篇是导读**——读完知道去哪、记什么、什么算完，细节对着两份 README 办。

## 共同骨架：文件名即状态机 + probe 必填

两本账共享同一套卡片纪律（todo/ 明文"借 hopissues 全套"）：

**文件名即状态机**：`编号_简单陈述_状态.md`——编号递增永不复用，状态就挂在文件名尾巴上（`open | pending | fixed | closed | declined`，hopissues 侧多一个 `reopen`）。状态变更=改文件名，必须用 `git mv`（历史即状态史）；`ls` 一眼看清全部卡的状态，这就是为什么不需要独立索引页。

**probe 必填**：每张卡必须写可执行的闭环判据——一条命令或一个可复现步骤，跑绿即证明问题真解决了。没有 probe 的事项说明还没想清楚，先想清再立卡。probe 是两本账最值钱的纪律：它把"我觉得修好了"变成"跑这条命令你自己看"。

**处置记录**：卡内逐条追加 `- YYYY-MM-DD <状态>（<git邮箱>）：<内容>`——给下一个读者写"为什么"，不是流水日志。

## todo/：本库内部账

装三类东西：

- **事项卡**（`0001_xxx_open.md`）：缺陷、缺口、待办——发现时立卡，修完自验 probe 绿即可 `git mv` 转 closed（库内单方，无需他方复验）；
- **技术债卡**：沿用九要素（需求/触发案例/当前替代/trade-off/涉及锚点/触发条件/工作量/状态）——**trade-off 写不出来的不是债，是偏离**，别拿债卡给偏离洗地；
- **主题计划文件**（`plan-<主题>.md`）：与作者对焦后的**多件事执行排列**——哪件先做、为什么这个顺序、作者拍过什么板。与事项卡的分工：卡=单件事的完整档案，计划=顺序与对焦语境。三条纪律记牢：主题名把话说全（没跟过对话的人一眼知道主题）；**对焦即落笔**（对话里排定顺序当场更新文件，不靠会话记忆）；行指卡不复写（计划里每项一行指向卡，细节归卡）。

日常动线：**接手一个主题先读对应 plan 文件**（顺序与语境在那里）→ 干活中发现新问题随手立卡（编号取当前最大+1，注意并行会话可能抢号）→ 修完 probe 自验 → `git mv` 流转。

## hopissues：跨项目通道

`../hopissues/` 是独立 git 仓库、两项目的共享通道，**按被报告方分子目录**（`hoplogic3/`=别人报我们的，`hopkb/`=我们报别人的——谁修归谁目录）。与 todo/ 的关键差异四条：

1. **fixed ≠ closed**：修复方修完标 fixed 只是半程——**closed 的唯一判据是报告方在自己环境把卡内 probe 实跑转绿**。probe 仍红就 reopen 并附实跑输出。这是跨项目账本比库内账多出的那道闸：修复方说"好了"不算数；
2. **署名两段**：处置记录行格式 `- YYYY-MM-DD <状态>（<项目>,<git邮箱>）：<内容>`——多一个项目段，标明写这条的 agent 站在哪个项目语境（它是状态段单写侧的判定依据）；
3. **改卡即推**：共享通道不 push 等于没写——对方看不见，通道失效。改完卡随手 `/usr/bin/git push`；
4. **接入义务**：开工扫描已接线本库 `check:fast`（`scripts/check-hopissues.mjs` 会报两个数：他方 fixed 待我们复验的、报给我们的 open/reopen）——**对方标 fixed 的卡，先跑 probe 复验再开新工**（绿→closed，红→reopen）；报来的 open 及时应答不长挂。

附件（日志切片、探针脚本）放卡的同名子目录，`git mv` 流转时连附件目录一起改名——**自查判据：`ls <目录>/<编号>_*` 只该有一个状态后缀**。

## 常见判断题

- "引擎有个 bug，我这就能修" → todo/ 立卡（或小事直接修，commit 里说清）；
- "引擎的 bug 是同事的项目报来的" → 它已经在 `../hopissues/hoplogic3/` 里——修完标 fixed 填修复 commit，**等对方 probe 复验**，别自己标 closed；
- "发现依赖的另一个项目文档有错" → `../hopissues/<对方目录>/` 立卡（probe 写清怎么验证），push，自己库最多留一行指针；
- "和作者对完焦，排了五件事的顺序" → `todo/plan-<主题>.md` 当场落笔；
- "这个功能先不做，等 X 条件成熟" → todo/ 立卡标 `pending`，**必写启动条件**（pending 不入待修计数，但没有启动条件的 pending 是死账）。

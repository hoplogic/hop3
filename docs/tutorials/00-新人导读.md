# 教程 0 · 从这里开始：你是哪类读者？

两类读者，两个系列——先选对线，别混着读。

## 🙋 我想**用**它：跑任务、写 spec、把自己的 skill 变可靠

走**用户系列**（编号即顺序）：

| 1 | [[01-第一次运行-ClaudeCode]] / [[01-第一次运行-Codex]] / [[01-第一次运行-cfuse]] / [[01-第一次运行-opencode]] | 入口四选一（按你用的工具），30 分钟跑通第一个 spec |

急用速查：`USAGE.md`（一页装和跑）；两种执行模式的取舍（复用入门 / 长任务转独立）：`USAGE.md` §6。配置字段查阅：`docs/reference/配置参考.md`（正式参考件——模型分档/凭证/工具注册全字段与优先级）。

**读多深由你定**：只跑现成 skill → 读到 1 就够；要看懂别人的 spec → 读到 2；想把日常杂活交给引擎管护 → 读到 4；要自己写 → 5-6；有存量 NL skill → 7；要接外部工具/服务 → 8；探索型的活 → 9。

## 🛠 我想**参与开发**：读懂概念体系、给引擎/工具链做贡献

走**生态开发者系列**：[[D0-生态开发者导读]]（十站主线：从工程实现链规范到模块收链、机检守卫）→ [[D1-用AI做工程-从概念到设计]]（上半场：概念→架构→模块→设计逐层收窄，设计用 HOP 三件套表达——人拍决策，AI 做推演）→ [[D2-用AI做工程-AIcoding与验收]]（下半场：怎么给 AI 派活、AI coding 的纪律、人用机检和锚点链验收——查链不逐行读码）→ [[D3-hopissues与todo的使用]]（两本账的分工与日常动线：todo/ 内部事项卡与主题计划、hopissues 跨项目通道与 probe 复验闭环）→ [[D4-架构讲解]]（引擎为什么长这样：模式无关核+双适配壳+Provider 边界，派架构级活前建全景）→ [[D5-错误与异常处理]]（失败挂在结构上：FailRecord/修复阶梯/未捕获终止/call 跨界）→ [[D6-用HopLog诊断]]（执行的完整历史：块怎么读、六个常见诊断问题的查法）→ [[D7-开发自己的工具]]（in-process vs MCP 两条路、接口契约与责任书）→ [[D8-模型与工具配置]]（配置地图、按步骤类型分档省成本、偏好语义与常见配方）→ [[D9-Obsidian可视化插件]]（深层 spec 的折叠/大纲/落点高亮，三步装进 vault）→ [[D10-hop_python计算体]]（agent 代写的受限计算体：四类能力、白名单、读得懂核得对）→ [[D12-新模型接入与验证]]（接新模型的四层测试：协议探针/引擎冒烟/纪律点名/能力定位——配上能跑不等于接好了）。

> 判据拿不准就看这条：**改的是 spec 还是 src/**？只写 spec、造 skill——用户；要动 `src/`、`docs/design/`、driver 层——开发者（且动手前必读 `docs/concepts/工程实现链规范.md`）。两条线不互斥，开发者通常先走一遍用户系列建立体感。

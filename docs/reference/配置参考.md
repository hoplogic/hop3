# HopJIT 配置参考

> **本文性质**：**对外配置契约的权威文档**（2026-08-13 作者定——对外契约的权威属对外文档,设计文档管实现）。用户写进配置文件的一切字段、文法与语义以本文为准；加载/合并/校验的实现行为契约在设计文档（[[../design/shared-providers]]/[[../design/tool-interface]]）。入门引导见教程系列。 ^anc-ref-config-contract

## 零、配置地图：什么住哪

**一份 schema，两个作用域** + 两个 spec 内配置位：

```
~/.hopjit/config.yaml      ← 系统级,跟着人走（一台机器一份;providers/凭证引用通常在此）
<项目根>/hopjit.yaml        ← 项目级,跟着项目走（可进仓库;可选——工具面通常在此）
    两文件同一 schema（providers/default_model/routing_rules/tool_servers/env/resource_limits/commands/log_level 八节全可选——与 shared-providers ^anc-config-standalone-schema 同一清单,两处此前各漏各的〔review 面一抓〕）
    逐节合并,项目级赢：providers 按 service_id、routing_rules 按 step_type 覆盖同键;
    tool_servers 取并集（不同名 server 间工具名跨级判重,冲突在 start_run 装配时拒——结构化 error TOOLS_NAME_CONFLICT;server 同名=项目级整体替换该 server 声明）

spec 文件内:
  Config: 段                ← spec 级,随 spec 走——本 spec 的模型分档/重试深度
  步骤 > @model 标注         ← 步骤级——单步模型覆盖
```

**同一 schema 为什么两个文件**：系统级装"你是谁、用什么后端"（换项目不变）；项目级装"这个项目要什么工具、要什么分档差异"（跟项目进仓库）。项目级文件可以只写 tool_servers 一节——providers 从系统级继承。in-process 扩展模块的 `module:` 相对路径按**声明所在配置文件**目录解析（项目级声明相对项目根）。

**层层可缺省**：全部不配也能跑（复用模式零配置；独立模式最小配置=一条 provider）。分档是优化不是义务。两级全字段的完整样例见 [[#^anc-ref-config-full-example|文末完整样例]]。

**改配置什么时候生效**（MCP server 常驻场景）：项目级 `hopjit.yaml` 的**数据面节**（`tool_servers`/`env`/`routing_rules`/`default_model`）每次 `start_run` 装配时重读——改完下一个 run 即见，不用重启 server；**`providers` 节例外**——凭证在 server 启动时解引用，改 providers（含项目级新加后端）须重启 server 才生效。文件写错（文法/凭证违规/引用拼错的 service）当次 run 直接拒（`CONFIG_INVALID`），不会静默用旧配置。CLI 单跑（非常驻）每次都是新进程，无此分层。

## 一、后端服务与凭证（config.yaml: providers）

独立模式（standalone）的后端声明。**文件绝不保存 key**——凭证只写环境变量名。

```yaml
providers:
  - service_id: deepseek        # 路由标识（字母数字下划线;default 是保留字）
    protocol: anthropic         # wire 协议,见下表
    base_url: https://api.deepseek.com/anthropic
    model: deepseek-v4-flash        # 该 provider 的默认模型
    api_key_env: DEEPSEEK_API_KEY   # 环境变量名——唯一合法凭证形态
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `service_id` | ✓ | 全局唯一（大小写归一判重）；`service/model` 引用的前半 |
| `protocol` | ✓ | wire 报文格式：`anthropic`=Anthropic Messages API 兼容；`openai-chat`=OpenAI chat/completions 兼容；`openai-responses`=Responses API（**预留未实装**——选它启动即报错并指路 openai-chat）。openai-chat 当下不支持无 body 的 act 工具循环 |
| `base_url` | ✓ | API 端点 |
| `model` | ✓ | 该 provider 缺省模型 |
| `api_key_env` | ✓ | 环境变量名引用（两道闸：出现 `api_key` 字段名即拒；`api_key_env` 值须匹配环境变量名文法。**不检测值内容**——把 key 本身填进 api_key_env 会到 preflight 才以『环境变量未设置』拒，凭证安全靠字段名纪律） |
| `max_output_tokens` | 否 | 该 provider 模型的单次输出上限（正整数）。**缺省 32768**——上限是物理防线不是产出配额：按用量计费下压小上限不省钱只制造截断（thinking 型模型 thinking+正文共池,压小了 thinking 烧满正文零字节）；产出多大由 spec 各步骤的输出声明约束。模型上限更高（如 64K 档）时在此声明放开 |

首条 provider 是全局缺省后端。

## 二、模型配置（跨三层,一个主题）

模型选择是三层配置位协作的一个主题——**系统层定环境的档位表，spec 层写自己在意的差异，步骤层做单点覆盖**。

### 系统层分档：config.yaml `routing_rules`（可选）

```yaml
routing_rules:
  - step_type: act        # 执行类（含 commit,除非另写 commit 条）——轻量档
    model: deepseek/deepseek-v4-flash
  - step_type: reason     # 推理——中强档
    model: deepseek/deepseek-v4-pro
  - step_type: check      # 核验——宜换一家（交叉验证防同源盲区）
    model: bailian/qwen3.7-plus
  - step_type: replan     # 重规划=元编程,须会写 HopSpec——最强档
    model: zhipu/glm-5.2
```

- `step_type` 枚举：`act` / `commit` / `reason` / `check` / `replan`（confirm/ask 是介入点无 LLM，不可路由）；
- `commit` 无专条时吃 `act` 条（执行类共档）。

另有 `default_model:`（可选）——系统级默认模型，`service/model` 或裸模型名；引用的 service 必须在 providers 内（拼错启动即拒）。

### spec 层分档：`Config:` 段

`Config:` 段写在 spec 头部（`Id:`/`Goal:` 之后、`## Inputs` 之前）。**Config 段就是一个 HopSchema 字段**——条目内外层都用 `-` 分项，与 Inputs/Outputs 同体例（spec 全篇一种分项心智）。当前支持两个键，都管模型：

```markdown
# Spec: 订单风险审查
Id: order-risk-review
Goal: 审查订单清单,产出风险分级报告

Config:
- models:                             # 类别分档——逐类别继承系统层,只写在意的差异
  - reason: deepseek/deepseek-v4-pro  # 本 spec 推理档
  - replan: zhipu/glm-5.2             # 重规划档（环境无 zhipu 时落系统分档,见偏好语义）
- model: deepseek/deepseek-v4-flash   # 单默认——models 没写的类别落这里（可省;省则落系统层）

## Inputs
- orders: yaml  # 订单清单

## Outputs
- report: markdown  # 风险分级报告
...
```

| 键 | 说明 |
|---|---|
| `models` | 类别→模型映射。类别=`act`（含 commit,另写 `commit:` 键可分）/`reason`/`check`/`replan`。**逐键继承**：只写在意的差异,没写的类别落 `model` 单默认,再落系统层 routing_rules——不是整块覆盖 |
| `model` | 单默认——全类别同值的简写；`models` 类别键比它优先 |

两键都可省——全省则整个 spec 用系统层配置。

**偏好语义（spec 面引用不炸）**：spec 里写的模型引用是**偏好**——环境里有这个 service 就用；没有则在执行日志留一条 warn，然后跳过这级沿优先级链继续向下（`models` 键 → `model` 单默认 → 系统分档 → 系统默认 → 内置缺省），**直到某级命中为止——链尾恒有缺省，必有归宿，不报错**。spec 由此天然可移植：写了 `zhipu/glm-5.2` 的 spec 在没有智谱的环境照常跑。系统层配置（providers/routing_rules/default_model）不适用偏好语义——它的检查在加载期就做完了：引用的 service 必须在同文件 providers 内，对不上直接拒绝启动（自己文件里前后不一致是笔误，不是环境差异）。

### 步骤层覆盖：`@model` 标注

```markdown
2. [reason] 分析舆情风险
  > @model deepseek/deepseek-v4-pro
  > 综合各渠道数据评估风险等级
```

单步覆盖，最高优先级。仅可执行步骤（reason/act/check/commit）有效。

### 解析优先级（完整链）

从 specific 到 general，第一个命中即生效：

```
1. 步骤 @model 标注
2. spec Config.models[类别]        ← 类别=act(含commit)/reason/check/replan
3. spec Config.model（单默认）
4. 系统 routing_rules[类别]         ← commit 无专条吃 act 条
5. 系统 default_model
6. 环境变量 ANTHROPIC_MODEL   ← 宿主环境继承——只有 Anthropic 系宿主（CC）会设;
                                Codex 的模型配置在 ~/.codex/config.toml（model= 键）不经 env 暴露,此级落空
7. 宿主 HostConfig.model      ← 引擎被当库嵌入时宿主代码注入——个人用户碰不到
8. 内置缺省
```

> 1-5 级是你配的；6-7 级是"你不配时引擎从运行环境里捡"的兜底，通常无需关心：复用模式引擎不调 LLM 用不上；standalone 必有 config.yaml，第 5 级即命中。**在 Codex 宿主下给引擎配模型的正道就是 config.yaml——没有 env 捷径。**

## 二b、spec 环境参数（env: 节） ^anc-ref-hop-env

spec 里引用的**环境配置参数**（材料库路径、知识库位置等非密值）——统一 `hop_env_` 前缀，写在配置文件 `env:` 节：

```yaml
# 系统级 ~/.hopjit/config.yaml 或项目级 <项目根>/hopjit.yaml（逐键合并,项目级赢）
env:
  hop_env_kb_root: ~/vaults/判据库        # 全名入配置——所写即所引
  hop_env_brand_root: ~/vaults/办公生产力
```

**覆盖链**（后者覆盖前者，逐键非整块——与 Config.models 继承同款心智）：

```
系统级 env: 节 → 项目级 env: 节 → start_run/params 传入 → spec 内 ask 问人
```

**spec 怎么用**：doc-ref 路径位直接引用——`[[{hop_env_kb_root}/入库判据#完备性]]`；hop_python body 里作只读变量可用。spec 需要哪些 hop_env 参数应在其说明中列明——你按清单在 env: 节填路径即可，**不需要关心"从哪个目录启动"**。

**三条硬规则**：
| 规则 | 说明 |
|---|---|
| 只读 | spec 不能改 hop_env_* 值（`+ →` 产出带此前缀=校验错）；ask 问人补值是覆盖链末级,合法 |
| 凭证禁入 | key/token **严禁**写进 env: 节——hop_env_* 会落盘入日志;凭证只走 `api_key_env`（环境变量名引用,不落盘） |
| 未定义即报错 | spec 引用了 env: 节里没有的键 → 该步响亮报错（不静默拼空路径找错文件） |

语言语义权威见核心规范 `^anc-config-hop-env`；doc-ref 展开细则（转义等）见语法参考。

## 三、工具面配置（tool_servers 节）

配置文件（通常项目级 `hopjit.yaml`）里直接写 `tool_servers:` 节：

```yaml
tool_servers:
  - name: hopkb
    binding:
      kind: mcp
      transport: stdio
      command: hopkb-mcp
    tools:
      - name: kb_search
        requires_commit: false
```

三种绑定形态与字段语义： ^anc-ref-tool-servers

| binding.kind | 附加字段 | 说明 |
|---|---|---|
| `mcp` + `transport: http` | `url`、`auth_env`（环境变量名） | 云端 MCP 服务 |
| `mcp` + `transport: stdio` | `command`、`args`、`env_passthrough`（白名单透传） | 本地 MCP 子进程（引擎监护起停） |
| `in-process` | `module`（模块路径,相对声明所在配置文件目录） | 隔离工具库装载进引擎进程 |

server 级可选 \`call_timeout_ms\`（单调用硬闸,缺省 60000）。每个工具条目：\`name\`（wire 名,可中文）、\`tool_id\`（body 调用名,name 非法标识符时必填）、\`requires_commit\`（必填——不可逆标记,act 拦/commit 放）、\`input_schema\`（JSON Schema,mcp 可省从发现补全）、\`output_schema\`（HopSchema——字段名→类型,只核顶层）、\`unwrap: json-in-text\`（响应解包）。

**白名单语义**：声明即启用——server 报 N 个工具只放行声明过的。实现行为（装配/双端校验/生命周期）见 [[../design/tool-interface#^anc-config-tool-registry]]；引导见教程 08。

**可抄样例**：
- `examples/hoptools-websearch.yaml`（web 检索,provider 中立形态——**tool_id 恒 `web_search` 解耦 provider wire 名,换后端只改配置 spec 零改**;含签名 params+notes 全字段;百炼形态已真机验证）＋配套端到端 spec `examples/websearch-brief.md`（真机 completed）;
- `examples/hoptools-playwright.yaml`（浏览器自动化,server=官方 @playwright/mcp 零自建——**白名单三档:只读观察 false/页面交互 true〔点击填表可能触发不可逆提交——commit 语境〕/evaluate·run_code_unsafe 不入白名单**;冷启动预热注;server 返回是散文文本——接值声明 text 非 yaml）＋配套端到端 spec `examples/webpage-extract.md`（navigate→snapshot→按关注点提取,真机 completed）。

## 三b、命令白名单（commands 节） ^anc-ref-commands

hop_python body 里 `subprocess.run` 能执行哪些命令，由 `commands` 键声明——**不配置就是一个都不能跑**（缺省安全，引擎不内置任何命令）：

```yaml
# config.yaml（系统级 ~/.hopjit/config.yaml）或 hopjit.yaml（项目级）
commands:
  - git
  - echo
```

- **按命令名收口**：`git` 放行后 `subprocess.run(["git", "worktree", "add", ...])` 可跑，参数不设白名单（参数是数据——参数列表制直接 spawn 不经 shell，参数里的分号只是字符）；
- **两级合并=并集**（系统级+项目级，与 tool_servers 同律）；
- **复用模式同用本键**：CLI 组合根读项目级 `hopjit.yaml` 的 `commands`（复用模式配置加载面为三个单键分别读取——commands/language/tool_servers，不引入完整配置合并；commands/language 坏配置钝感回缺省，tool_servers 坏配置响亮拒 CONFIG_ERROR）；
- 把外向命令（`git push` 这类）放进名单要想清楚：v1 无 requires_commit 级机器拦，放了=自担 act 位可重跑后果（执行契约见 design/act-body ^anc-exec-subprocess-run 工程偏差①）。

## 四、完整样例（两级全字段） ^anc-ref-config-full-example

**系统级 `~/.hopjit/config.yaml`**（跟人走——后端、凭证引用、环境分档）：

```yaml
# 后端服务（至少 1 条;首条为缺省后端。key 永不入文件——只写环境变量名）
providers:
  - service_id: deepseek              # 路由标识,service/model 引用的前半
    protocol: anthropic               # deepseek 原生支持 Anthropic Messages 格式
    base_url: https://api.deepseek.com/anthropic
    model: deepseek-v4-flash
    api_key_env: DEEPSEEK_API_KEY
  - service_id: bailian
    protocol: openai-chat             # 百炼 OpenAI 兼容端点走 chat/completions
    base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
    model: qwen3.7-plus
    api_key_env: DASHSCOPE_API_KEY
  - service_id: zhipu                 # 智谱 GLM 经百炼取用（同端点同 key——百炼是多家模型的代理面,
    protocol: openai-chat             # 单开 service 条目让 zhipu/glm-5.2 引用语义清晰）
    base_url: https://dashscope.aliyuncs.com/compatible-mode/v1
    model: glm-5.2
    api_key_env: DASHSCOPE_API_KEY
  - service_id: anthropic
    protocol: anthropic
    base_url: https://api.anthropic.com
    model: claude-sonnet-4-6
    api_key_env: ANTHROPIC_API_KEY

# 系统默认模型（可选;不写则用首条 provider 的 model）
default_model: deepseek/deepseek-v4-flash

# 执行日志级别（可选,debug|info|warn,缺省 debug——standalone 的执行内幕全在 server 进程内,
# 日志是唯一核验通道,debug 记 LLM prompt 全文;日志体积在意时降 info（只记 model/tokens 与 I/O 值））
log_level: debug

# 系统级模型分档（可选——环境的档位表,spec 没配的类别继承这里）
routing_rules:
  - step_type: act                    # 执行类（含 commit,另写 commit 条可分档）——轻量档
    model: deepseek/deepseek-v4-flash
  - step_type: reason                 # 推理——中强档
    model: deepseek/deepseek-v4-pro
  - step_type: check                  # 核验——换一家交叉验证（主力 deepseek,核验走 qwen）
    model: bailian/qwen3.7-plus
  - step_type: replan                 # 重规划=元编程,须会写 HopSpec——最强档
    model: zhipu/glm-5.2

# 系统级通用工具（可选——所有项目都要的工具放这;项目专属工具放项目级）
tool_servers:
  - name: bailian_search
    binding:
      kind: mcp
      transport: http
      url: https://dashscope.aliyuncs.com/api/v1/mcps/WebSearch/mcp
      auth_env: DASHSCOPE_API_KEY
    tools:
      - name: bailian_web_search
        tool_id: web_search           # body 调用名（name 已是合法标识符时可省）
        requires_commit: false
        output_schema:                # HopSchema:字段名→类型,只核顶层
          pages: [yaml]
        unwrap: json-in-text          # 百炼系惯例:JSON 塞在 text 块里
```

**项目级 `<项目根>/hopjit.yaml`**（跟项目走可进仓库——只写差异,其余逐节继承系统级）：

```yaml
# 本项目的分档差异（可选——只覆盖 reason,act/check/replan 照用系统级）
routing_rules:
  - step_type: reason
    model: anthropic/claude-opus-5    # 本项目推理任务重,reason 超配到最强档

# 本项目的工具面（与系统级取并集;工具名跨级重名 start_run 装配时拒）
tool_servers:
  - name: hopkb                       # 本地 MCP 子进程（引擎监护起停）
    binding:
      kind: mcp
      transport: stdio
      command: hopkb-mcp              # PATH 可达或绝对路径
      args: ["--kb", "./kb"]
      env_passthrough: [HOPKB_HOME]   # 白名单透传——不整包漏环境
    call_timeout_ms: 120000           # 可选:该 server 单调用硬闸（缺省 60000）
    tools:
      - name: kb_search
        requires_commit: false
        input_schema:                 # JSON Schema（mcp 可省——从 tools/list 发现补全）
          type: object
          properties:
            query:
              type: string
          required: [query]
        output_schema:
          hits: [yaml]
      - name: kb_write                # 出箱写操作——act 内调用即拒,只许 commit 步骤
        requires_commit: true
  - name: word_stats_lib              # in-process 扩展模块（隔离工具库装载进引擎进程）
    binding:
      kind: in-process
      module: ./ext-tools/word-stats.mjs   # 相对本文件（项目根）解析
    tools:
      - name: word_stats
        requires_commit: false
        output_schema:
          words: int
          chars: int
```

## 二、探针实测数

### G1 手算乘除法（正确率 ≥90% 的最大位数，贴线档 20 发确认）

| 任务 | deepseek | Ling | qwen27 |
|---|---|---|---|
| 乘法 N位×N位（直接推理） | ≥12（测程顶） | 6 | 3 |
| 除法 2N÷N 商 2N+1 位有效数字（迭代推理） | ≥8（测程顶） | 6 | 2 |

Ling 的数字是开思考档（它的可用能力）——端点缺省关思考，不开只有乘 2/除 <2，所以重推理步派 Ling 必须显式开思考（配置方法见岗位表下方成本手柄）。规律一条：迭代档恒低于直接档（一步错步步错的长链更早塌）。

读数三条纪律（详见 D12）：通过率当概率读（2/6 = 单次成功率约 1/3，配 retry=K 的成功率 ≈ 1-(1-p)^K）；任务尺寸按实际拆出的要素数对档，不按字节猜；概率读数的消费出口是并发并集，不只是加重试。

注意：思考型模型（deepseek）测提取类任务必须给足输出预算（思考与正文共池，预算不足会把预算病误记成能力病）——探测方法见 D12"思考开销探测"节。

### 切块尺寸标定（XL 语料 40 点答案键，覆盖率百分比）

| 配置 | deepseek | Ling | qwen27 |
|---|---|---|---|
| 整篇一发 | 100 | 82.5–100（波动） | 100※ |
| 块=8 行 | 100 | 87.5–95 | 97.5 |
| 块=16 行 | 100 | 95–100（n=6） | 97.5–100（n=6） |
| 块=32 行 | 100 | 92.5–95 | 97.5 |
| 最优块×3 并发并集 | 100 | 100 | 100 |

※ qwen27 整篇形态对提示词敏感（与 G2 探针 2/6 不一致），不可靠，切块仍是正解。

结论三条：

1. **deepseek 预算给足后整篇直做即可，不需要切块**；
2. **Ling/qwen27 切块的作用是抬底不是封顶**（Ling 整篇最低 82.5% → 块 16 最低 95%），建议块大小 16 行；
3. **3 并发取并集三家全部收敛 100%**——各实例漏的是不同的点（漏点集中在推演型断言），并集覆盖率恒不低于最好的单份。并发冗余是概率型步骤的标准配置（适配方法 9）。

### G6 代码生成——Python 与 SQL（n=6，隐藏测试判分，自愈回路最多 2 轮）

两种语言各三档。Python 题=把一条规范条款写成校验脚本，在引擎 run_script 的真实环境里跑（先过 Python 语法沙箱），看隐藏测试文件上的退出码；SQL 题=按取数需求写一条 SQLite 查询，每份测试数据单独建临时库，结果集逐行逐列全等才算对。表内每格是"一次写对 / 自愈后通过"。

| 档 | deepseek | Ling | qwen27 |
|---|---|---|---|
| Python 简单：每行不超过 100 字符 | 6/6 / 6/6 | 6/6 / 6/6 | 6/6 / 6/6 |
| Python 普通：函数不超过 40 行 | 6/6 / 6/6 | 2/6 / 4/6 | 4/6 / 6/6 |
| Python 复杂：公开函数的文档字符串要提到每个参数 | 3/6 / 6/6 | 1/6 / 2/6 | 3/6 / 5/6 |
| SQL 简单：单表筛选排序 | 6/6 / 6/6 | 6/6 / 6/6 | 6/6 / 6/6 |
| SQL 普通：左连接加分组聚合 | 6/6 / 6/6 | 5/6 / 5/6 | 6/6 / 6/6 |
| SQL 复杂：每个用户的最长连续登录段 | 6/6 / 6/6 | 5/6 / 5/6 | 6/6 / 6/6 |

- **失败形态分账**：deepseek 40 轮提交零沙箱拒绝，Python 复杂档一次写对的 3 发失手全是输出截断（撞到 32768 输出上限、正文为空），交出了脚本的全对；qwen27 42 轮提交 6 轮被沙箱拒（hasattr 等）；Ling 50 轮提交 15 轮被沙箱拒（f-string 冒号格式、re.compile 等），复杂档到最后仍有 2 发被拒；
- **公开过隐藏挂**（模型看得见的样例全过、隐藏测试挂——规约内自验把关拦不住的一类）：Ling 共 6 发（Python 普通档漏查类方法 2 发、Python 复杂档把函数体内的嵌套函数也查了 2 发、SQL 普通档漏数金额为 NULL 的已支付订单 1 发、SQL 复杂档没收成每人一行 1 发）；qwen27 1 发（Python 复杂档漏查仅位置参数）；deepseek 0 发；
- **同一模型两种语言可差两档**：Ling 与 qwen27 的 SQL 都明显好于 Python；
- 每道题的隐藏测试都做过负向验证：常见的错误写法（左连接条件写进 WHERE、客户数被扇出放大、参数名子串匹配、大小写不敏感匹配、同额不按 id 倒序等）每一种都至少挂一份隐藏测试；
- HopSpec 语言的写作能力不在本探针，由 hopbuild2 构建卷考；"大规模复杂"档（多文件协作级）还没有题。第一版题目的复杂档是 TypeScript 题，作者定"编程能力考 Python 和 SQL"后撤下（commit `7251cf7f` 可查旧数据）。

### 思考开销（thinking 型模型专属，deepseek 实测）

- 思考与正文共用输出预算池，思考量随任务规模增长（40 点提取任务实测思考 1.5–1.8 万 token）；
- **机械步（提取/格式转换/照单填表）关思考：得分持平、费用降 8–9 倍**（40 点提取：开 1.7–2 万 token vs 关 2190）；
- 关思考不等于不推理——推理迁移到正文（12 位×12 位手算乘法关思考 4/4 全对，每发 2–3 千 token）；
- 硬边界：**工具编排步恒不关**（实测关思考后工具循环打转 20 轮烧尽）；判官类未对照，暂不进关思考白名单；
- 落地手柄：步骤级 `@thinking on|off` 标注（0.17.0 起）+ provider 级 thinking 缺省键，五级优先链详见配置参考。

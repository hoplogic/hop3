## 归属一：hopjit 引擎问题（两条，均已修复+真机验证）

1. **交付格式例教错形态**（^anc-exec-format-example-structural）：格式例把 yaml 型渲染成 `名: |` 块标量占位，Ling 照抄致五轮 SCHEMA 烧死。修=格式例按值性质分形。验证=Ling hb2 同语料复跑死点越过；
2. **HopSchema 渲染语法回声**（恢复阶梯家族第 6 马甲）：输入渲染的 `名: 类型 = 值` 语法被 deepseek 照抄进输出（19 个并行子实例 2 个回声，≈10% 惯性率），毒值过校验炸下游机械对账成"同点双清单"矛盾，改产物永远修不平。修=stripSchemaEcho 整串匹配剥壳+递归进结构。验证=deepseek S 复跑 completed 零污染。

共同病理=**模型逐字复读引擎供给形态**；共同定律=**教学清不了零**（教学完整在场照样犯，惯性不分强弱模型），防线必须机械。

## 归属二：hopspec 写法问题（四条，均已修+复跑翻绿）

全部出自 qwen 微判定变体的判据边界，特征=每条具体、修完不复发、失败逐轮收敛（微判定框架的健康形态）：

1. 一行多断言并列时小题失焦（"成立近8年来"逐字在场判缺）→ 小题改三步显式核销；
2. 真假阴性无兜底 → 2.6 机械汇总加"missing 是 claims 子串即机械改判"；
3. 标题行被当断言源（判官要求把标题名词短语提成事实点）→ 小题判据加"标题行与裸名词短语不算断言"；
4. retry=2 遇缺口跨轮漂移打地鼠耗尽 → 放宽 retry=3。

修后 qwen S 从两轮全烧尽翻绿完赛。另有一条引擎面挂账未修：schema 打回整批丢弃（17 点最优提取因一个坏字段全批报废）——[T] 逐元素校验只打回坏元素，挂 0095。

## 归属三：变速箱适配问题（三条，换挡不修 spec）

1. **qwen M 档提取**：信息密集行的多断言拆分不动（L3 一行五断言只提一条，75 点总量却漏关键行）——G2 界（引擎内 2~4 要素）的真实任务表现。对策=用按它的能力档定制的构建产物（D98 目标执行档模式，每步 ≤4 要素）或不派它干 M+ 档提取；
2. **Ling fact-check L 档**：判官三轮三套标准且轮间口径对调（42 条要求版权声明当事实点→下轮全部不提→再下轮要求预测句整批改 fact），提取侧每轮真改进、验收目标永远移动。**spec 判据已明文写着防摇摆条款，Ling 读了照犯**——P1 checklist-only 档在开放式判官岗位上的必然死相。换挡=L+ 档不让 Ling 跑母本开放判官（用微判定变体，或判官路由强模型）；
3. **Ling dv M 档**：自检表态两头占（同一 warning"采纳为风险"+"误报不构成风险"）+ 后续轮编造依据（声称"所有 write 路径指向 work_zone"而被审件零写盘）。qwen 同件同 spec 1.4 万完赛是最强对照——超界的是 Ling 不是卷。换挡=dv 判官岗按 P1 档路由。

## 跑批工装教训（自账）

1. 语料卫生：抓取件的页脚残渣/出处头/正文重复都会被判官当真内容较真——语料入库前剥净，出处独立成 PROVENANCE.md；
2. spec 现拷要连 doc-ref 伴随件一起拷（dv 六件全撞进闸拒）；
3. 止损帽按任务真实成本设：真实 fact-check M 档 138 万 tokens，100 万帽会把正常运行误杀；
4. 同工作区多轮 run 的 vars 残留会污染事后分析——glob 按 mtime 取最新，或每轮清工作区（本轮曾因抓错旧 run 文件差点误判修复无效）。

## 对三层的结论句

- **hopjit**：本轮暴露的两个引擎缺陷都属"供给形态被复读"家族且都已修——引擎主链（重试/收割/校验/恢复）在三模型 13 件真实任务里零主链事故；
- **hopbuild2/hopspec**：微判定框架实证有效（失败收敛可修，qwen S 翻绿）；判据写法的边界（标题行/多断言/兜底）是持续打磨面，已进教学的三规矩+本轮四修都该随 D98 教学更新；
- **变速箱**：三条适配结论全部落档案消费——真实任务阶梯比合成探针多测出的正是"能力界在真活上的表现形态"，这就是这条阶梯的存在价值。

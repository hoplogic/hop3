# code-generation — G6 代码生成探针（Python 与 SQL 两种语言）

判据方法论权威=`docs/tutorials/D12-新模型接入与验证.md` G6 节；本目录只管题目、测试文件与跑法。

## 测什么

考两种语言：**Python 和 SQL**，各分简单 / 普通 / 复杂三档。两种语言对应引擎场景里模型要写的两类代码：Python 是 hop_python body 与 run_script 校验脚本，SQL 是数据处理类 skill 的取数查询。

**Python 题**：每道题是一条规范条款，模型要写一个 Python 校验脚本：从 `sys.argv[1]` 读待查文件，合规时退出码 0，违规时逐条打印违规并退出码 1。这正是 `standard-decompose-codify` 规约步 5.1.1 要模型干的活，所以本探针同时是 sdc 这类任务的能力前置检查：先知道模型能不能写对校验脚本，再去看它在规约里的表现，两类失败才分得开（协议或规约写法的问题 vs 写代码本身的问题）。

脚本在引擎 `run_script` 的真实环境里执行：先过 Python 语法沙箱（`dist/py-sandbox.js`，与引擎同一份实现），审过才跑。题面把沙箱白名单全列给模型，测的是写代码的能力，不是猜白名单的能力。

**SQL 题**：每道题是一个取数需求加表结构，模型要写一条 SQLite 查询。判分时每份测试数据单独建一个临时库（建表 + 插数），以只读方式打开后执行模型的查询，结果集逐行逐列和期望比对——行的顺序要对，列名不比。SQLite 用 Node 自带的 `node:sqlite`（Node 22.5 以上），不需要另装依赖。

## 题目在哪儿

模型收到的一道题由三块拼成，分别放在三处。拼装由跑批脚本 `../run-code-generation.mjs` 完成，每道题第 1 轮发给模型的那条消息按下面的顺序拼：

1. **题目正文**：放在 `tasks/<题>.md`，一题一个 markdown 文件，Obsidian 里可以直接看。文件里「## 题目正文」一节的原文发给模型：Python 题是规范条款加规则细节，SQL 题是取数需求加规则细节。SQL 题还有「## 表结构」一节，节内 ```` ```sql ```` 代码块里的建表语句也发给模型，判分建临时库时用的也是这一份。文件开头的 frontmatter 记 `id`（必须与文件名一致）、`lang`（`python` 或 `sql`）、`level`（简单 / 普通 / 复杂）；一级标题和引用块里的说明是给人看的，不发给模型。**想看或改某道题考什么，打开这个文件。**
2. **固定外框**：同一种语言的所有题共用，写在跑批脚本里：
   - Python 题用 `buildPythonPrompt` 函数，外框写的是脚本接口要求（从 `sys.argv[1]` 取文件、合规退出 0、违规逐条打印后退出 1），再加 `SANDBOX_RULES` 常量（沙箱白名单全文）；
   - SQL 题用 `buildSqlPrompt` 函数，外框写的是执行环境（SQLite 版本、只读库、只交一条查询）。
   - 外框的最后一句都是"把代码放在一个代码块里交付"。
3. **公开样例**：放在 `public/`，拼在消息末尾，把文件内容原文给模型看。Python 题每题两个文件，`<题>_ok.*` 应判退出 0，`<题>_bad.*` 应判退出 1。SQL 题每题一个 `<题>.yaml`，里面是插数语句和期望结果集。

`tests/<题>/` 下是判分用的测试，本文叫"隐藏测试"。**这里的隐藏，是对被测模型隐藏**：人可以随便看、随便改，参考解和跑批脚本也都读它，它就放在仓库里。被测模型看不到它，靠的是跑批脚本的调用方式：脚本直接调模型 API，只发对话消息，不给模型任何读文件的工具；而消息里只有上面三块，没有这些测试文件的内容，自愈轮的反馈里也没有。所以被测模型能拿到的，只有题面和公开样例。

为什么要对被测模型隐藏：被测模型如果看得到判分用的测试，就可以照着测试凑答案，写出"恰好过这几个文件"的代码，测出来的就不是它照规则写代码的能力了。公开样例和隐藏测试分开，才量得出"公开过隐藏挂"这种失败，也就是模型自己验过的代码拿到没见过的文件上失效。

## 目录

| 位置 | 内容 |
|---|---|
| `tasks/<题>.md` | 题目文件，一题一个（结构见上节）。题面必须写全隐藏测试考到的每一个边界——考的是"照规则写对"，不是猜规则。文件缺「## 题目正文」一节、SQL 题缺「## 表结构」一节或其中的 sql 代码块、frontmatter 缺字段或 id 与文件名不符，跑批脚本都直接报错退出 |
| `public/` | 公开样例，拼进题面给模型看；自愈回路也只反馈模型的代码在公开样例上的实跑结果。Python 题每题两个文件 `<题>_ok.*`、`<题>_bad.*`；SQL 题每题一个 `<题>.yaml`（格式同隐藏测试） |
| `tests/<题>/` | 隐藏测试（对被测模型隐藏，人可以看，见上节）：内容不进题面，自愈轮也不把它的判分结果反馈给被测模型。Python 题：一批待查文件，文件名 `ok_*` 应判退出 0、`bad_*` 应判退出 1。SQL 题：每份 yaml 是一组测试数据，含 `data`（往空表里插数的 INSERT 语句）和 `expect`（期望结果集，每行一个数组） |
| `reference/<题>.py` 或 `.sql` | 参考解，仪器自检用：它必须在全部隐藏测试和公开样例上全对 |
| `run-<服务名>-<日期>/` | 一次跑批的产物（服务名是 `--service` 参数的值，比如 `run-deepseek-2026-09-23`）。里面三种文件：`<题>-<第几次>-r<轮>.txt` 是模型那一轮回复的原文（`r0` 是第一次作答，`r1`、`r2` 是自愈轮）；`<题>-<第几次>-grading.yaml` 是这次作答每一轮的判分记录（沙箱有没有拒、公开样例过没过、隐藏测试挂了哪几个文件）；`summary.yaml` 是全部题目的汇总指标 |

现有六题：

| 题 | 语言 · 档 | 考什么 | 隐藏测试考的边界 |
|---|---|---|---|
| `line-length` | Python · 简单 | 每行不超过 100 个字符 | 按字符数不按字节、CRLF 的 `\r` 不计、末行无换行、恰好 100 合规 |
| `func-length` | Python · 普通 | 函数不超过 40 行 | 装饰器不计、async 函数与类方法、嵌套函数各自计、恰好 40 合规 |
| `docstring-args` | Python · 复杂 | 公开函数必须有文档字符串且提到每个参数 | 五类参数（仅位置 / 普通 / `*args` / 仅关键字 / `**kwargs`）、self 与 cls 豁免、下划线开头的不查、函数体内的嵌套函数与局部类不查、类里嵌套类的方法要查、async 方法、整词匹配（count 不在 recounting 里）、大小写敏感、函数体后面才出现的字符串不算文档字符串 |
| `sql-filter` | SQL · 简单 | 单表按条件筛选排序 | 时间两端含（3 月 31 日当天全天）、金额恰好 100、NULL 金额、status 大小写与空格、同额按 id 倒序、空结果 |
| `sql-join` | SQL · 普通 | 左连接 + 分组聚合 | 没有已支付订单的地区也要出（左连接条件放 ON 不放 WHERE）、一个客户多单时客户数不能被放大、NULL 金额计单数不计金额、找不到客户的订单不计、空值输出 0 |
| `sql-streak` | SQL · 复杂 | 每个用户的最长连续登录段 | 同日多次登录去重、跨月跨年跨闰日按日历相邻、多段同长取最早、行无序 |

每道题的隐藏测试都做过**负向验证**：拿常见的错误写法（如左连接条件写进 WHERE、`COUNT(c.id)` 被扇出放大、日期按文本差算、参数名用子串匹配、漏查仅关键字参数）去跑，每一种都至少挂一份隐藏测试——拦不住的错误写法说明测试有缺口，补测试再上。

## 跑法

```bash
node model-gearbox/probes/run-code-generation.mjs --selfcheck                  # 仪器自检,零模型调用
node model-gearbox/probes/run-code-generation.mjs --service <service_id>       # 每题 n=6,自愈最多 2 轮
  [--n 6] [--heal 2] [--task <题id>] [--max-tokens 32768] [--out <目录>]
```

需要先 `npm run build`（探针直接引用 `dist/py-sandbox.js`），本机有 `python3`，Node 22.5 以上（SQL 题用 `node:sqlite`）。`--task` 可给多个题 id，逗号分隔。

**改题面、改测试文件、改沙箱白名单之后，先跑 `--selfcheck`**——参考解挂了说明仪器坏了，这时测出的模型分数没有意义。改沙箱白名单时还要同步 `run-code-generation.mjs` 里的 `SANDBOX_RULES` 段（给模型看的白名单说明）。

## 指标

- **一次写对**：第 1 轮交的解在全部隐藏测试上全对（Python 退出码全对，SQL 结果集全等）。裸能力，决定能不能当 body 生成主力；
- **自愈后通过**：回路结束时最后一版脚本全对。回路只反馈沙箱拒绝报文（Python）、执行报错与公开样例的实跑结果，最多 2 轮；公开样例一过就停（模型看得见的信号只有这些）；
- **公开过隐藏挂**：模型看得见的样例都过了，隐藏测试却有挂——"自己验过的校验拿到真实文件上失效"，sdc 类任务里最危险的一种失败，因为规约内的自验把关拦不住它；
- **首轮沙箱拒绝 / 首轮截断 / 首轮崩溃**：失败形态分账。截断（`stop_reason=max_tokens`、正文为空）是输出预算问题，不算写码能力。崩溃=脚本抛了未捕获的异常：Python 崩溃时退出码同样是 1，和"查到违规退出 1"在退出码上分不开，所以判分时单独认——stderr 里有 `Traceback (most recent call last)` 或退出码不是 0/1 的一律记崩溃、算判错，否则一个见文件就崩的脚本会在全部 `bad_*` 文件上白拿分。SQL 题的崩溃=查询执行报错（语法错、引用不存在的列等）。

## 扩展位

D12 G6 定义的是 Python / SQL / HopSpec 三种语言 × 简单 / 普通 / 复杂 / 大规模复杂四档。本探针只考 Python 与 SQL 的前三档；HopSpec 语言的写作能力由 hopbuild2 构建卷另行考察，"大规模复杂"档（多文件协作级）待后续批次。加题=`tasks/` 下一个题目文件 + `tests/` 一个目录 + 公开样例 + 参考解一份，自检过了、负向验证拦得住常见错误写法才算加完。

# extract-scaling — 结构化提取的尺寸阶梯簇

**测什么**：模型在"从文档提取 N 个结构化核查点 + 通过完备性验收"任务上的**尺寸-成功率曲线**——**G2 任务复杂度（一次做正确的能力）的主仪器**（首轮通过率按要素数递增记坍塌点）,兼测 G5 结构化交付（schema 形态错误率）与 P3 修订落实（指令散文序列理解——修订轮成功率,详见 D12 实践维度表）（缘起：Qwen3.8-27B 百炼件在 hop-fact-check 步骤 2 三轮烧尽——2 轮完备性打回 + 1 轮 schema 散文形态，这是它换掉走样端点后暴露的**真实能力边界**，值得参数化测出边在哪）。

## 语料阶梯（文档尺寸=断言密度双升）

| 档 | 文件 | 答案键 | 体量 | 预期核查点数 | 结构复杂度 |
|---|---|---|---|---|---|
| XS | doc-xs.md | doc-xs.key.yaml | ~130B | 2（1 fact + 1 inference） | 单前提 |
| S | doc-s.md | doc-s.key.yaml | ~290B | 4（2+2） | 单前提 |
| M | doc-m.md | doc-m.key.yaml | ~740B | ~9 | 多前提推演点+复合断言在场（=hop-fact-check 原样本，A2 实测死点） |
| L | doc-l.md | doc-l.key.yaml | ~1.5K | ~18 | 多前提+跨段对照断言（同一事件两段两说） |

答案键=判分的独立事实源（每键注释里写明比对口径：required 逐条必对上,多提不扣,漏提/错分类即不过）。语料改一字,键同步改——键与语料是一对连体文件。

## 跑法

被测 spec=`examples/hop-fact-check.md`（原件现拷），只跑到步骤 2 收口即可判（后续检索环节不属本簇考点——想省额度可在步 2 完成后 stop_run，points 已可从 vars 取出）。每档 n≥6（批间反转教训）。

```
# 工作面从原件现拷,hopjit.yaml 指目标模型
start_run(spec_path=<面>/hop-fact-check.md, params={"doc_path": "doc-<档>.md"}, workspace_dir=<面>)
```

## 每档判据（机械可判）

**判据独立性纪律（2026-09-18 作者抓"check 也是 27b 自己完成的"后立）**：run 内的完备性验收 2.4 由被测模型自己执行——被测者兼阅卷人，档位越大自评越不可信（点数多了漏项自己看不见）。故探针判"过/不过"**不采信 2.4 的自评结论**，判据分两层：schema 形态闸取引擎机械判（SCHEMA_MISMATCH 计数，模型说了不算）；提取完整性对**语料随附的标准答案键**机械比对（每份语料文档配一份 `doc-<档>.key.yaml`：预期点数+每点的 type/line_ref；产物点集对键逐条对得上才算过）。2.4 的自评结果另记一列（自评宽严度本身是反馈修正维度的数据）。首批 XS ✅ 已按此追认：产物经人工对语料核对，两点分类/引用/前提补全全对，非仅自评过关。

- **通过率**：提取产物对答案键比对过关的比率（不是 2.4 自评过关率）；
- **首轮完整度**：首轮提取的点数 / 语料预期点数（漏多少）；
- **schema 形态错误率**：SCHEMA_MISMATCH 打回占比（散文非数组类）；
- **反馈修正有效性**：被打回后下一轮是否真补齐（对比两轮 points 差异——原地重交=修正无效）。

## 产出与消费

曲线进 profiles 档案新段 `extract_scaling:`（形态同 act_free.reliability_curve：每档 {pass_rate, n}）。路由消费：曲线的坍塌点=该模型可承接的"单步提取任务尺寸上限"——hopbuild2 给该模型出产物时提取类步骤按此上限切分（大文档拆多轮小提取）。

## 维度修正（2026-09-18 首跑验尸后——真变量不是点数）

M 档六轮验尸实锤：提取能力在场（第 2 轮即交出基本正确的 8 点数组）、反馈理解在场（第 4 轮把拆分分析都推对了）、**死点=增量修订的落实**——分析写在思考文字里，交出的数据原样不动（"说到、想对、做不到"：推理区与行动区断连）。S 档三攻另实锤：**带修正上下文的重试轮 schema 服从性劣化**（首轮散文→自愈成数组→修正指令一来又退回散文）。故真变量三个,语料矩阵按此扩：

1. **点数规模**（XS/S/M/L 既有阶梯）;
2. **复合断言在场性**——每档语料出含/不含两版（一句话混多个独立 claim 要求拆分——M 档 L10-L11 正是全部打回的病灶句）;
3. **修订轮深度**——首轮成功率与"被打回后按意见改对"的成功率分开记（后者是主指标:它才是引擎重试机制价值的兑现面）。

**边界初判**：首轮纯提取的界在 2~4 点之间就开始不稳；修订落实能力≈0（两档合计 0/9 轮修订成功）。deepseek-flash 全档基线待跑。

## 修订短 prompt 对照实验（2026-09-18,作者假设"修正任务不佳,可能是任务隔的太远"的验证）

**实验设计**：取 S 档第 3 攻修订轮的真实供给做 A/B——对照组=引擎标准态全量 prompt 原件（15330 字符:280 行"从头作业"教学框架+尾部 73 行修正块）;实验组=手拼修订短 prompt（2575 字符:任务一句话+原文材料+上一版基准+打回意见+落实规则+交付格式,**刻意不含从头教学框架**）。同端点（百炼）同参数各 n=6 直连。

**结果（三关机械判;这次实验是手拼考卷,产物当时放在临时目录,已丢失——可复跑的库内仪器与五模型重测见下一节）**：

| 判据 | 短 prompt | 标准态全量 |
|---|---|---|
| schema 形态（首字符即 points: 零散文前置） | **6/6** | **0/6**（六发全散文前置,前缀 103~258 字符——与真机三攻死相同型） |
| 意见1 落实（L2 整句并回事实点） | 6/6 | 6/6（剥散文后判） |
| 意见2 落实（安全推演点补**具体数值**前提） | **6/6**（"每杯约 95 毫克,四杯共约 380 毫克"） | **0/6**（六发全是"四杯含量不超过 400 毫克"的循环复述,无数值） |
| 基准保留（未点名的 P1 原样） | 6/6 | 6/6 |

**结论**：**修订落实 0/9 的病理坐实=从头生成框架压倒修正指令,不是模型改不动**。同一个模型、同一份意见、同一个端点:砍掉教学框架后修订三关全绿;框架在场则形态必崩（散文前置 6/6 复现）且意见落实打对折（能"并句"这种编辑类动作,做不出"补具体数值"这种需要跳出上一版内容的增补——它在框架下是重做全题,重做时只会复读已有材料）。"任务隔太远"方向对,更准的表述是**框架占比**:修正块不是被距离稀释,是被 280 行从头教学的任务框架整体压制（强模型能整合"框架+意见"成修订任务,这档模型跟着篇幅大头走）。

**适配含义（挂 0095 批实装）**：弱模型档重开修订短 prompt 作 adapt 开关候选（`revision_prompt: short`）。**不推翻母本废除决策**——2026-08-31 的废除 A/B 是强模型跑的,三条废除依据里"质量打平"只对强模型成立;弱模型档按 model-gearbox 分界判据走变体/开关路线,正好是"只对某档模型必要、对强模型是无谓降级（缓存全失+质量无增益）"的教科书情形。

## 修订落实 A/B 库内仪器与五模型重测（2026-09-28）

**仪器**：`../run-revision-ab.mjs --service <service_id> [--n 6]`。和上一节手拼实验的区别是**考卷由引擎真实装配，不手拼**：以 `examples/hop-fact-check.md` 跑本目录的 S 档语料 `doc-s.md`，推到提取步 2.3，交一份内嵌在脚本里的"上一版"提取结果，在验收步 2.4 用内嵌的两条打回意见打回，引擎重跑读文档的两步后回到 2.3，这时取引擎为修订轮装配的上下文渲染成两份考卷——两臂唯一的差别是引擎修订档 `standard`（标准态全量修订 prompt，约 1.46 万字符）和 `short`（修订短 prompt，约 3500 字符）。两份考卷原样存进产物目录，引擎改了之后重跑就是新卷。

**上一版的两处毛病（打回意见就针对这两处）**：

1. P5 的前提"四杯标准咖啡的咖啡因总量不超过 400 毫克"是把结论换个说法重复一遍——要求补上"一杯大约多少毫克"的具体数值和四杯总量（增补型修订，上一节实验里标准态 0/6 就栽在这一类）；
2. P2—P5 的行号是按原文两行分的，引擎给的是按句拆成四行的编号——要求逐个改成 L2/L2/L3/L4，P1 不许动（编辑型修订）。

**判分四关（每发机械判，四关全过才算改对）**：形态（5 个元素、六字段齐、编号 P1—P5）；意见一落实（P5 前提里有 40—200 毫克之间的每杯数值，且写出了它的 4 倍）；意见二落实（行号全对）；基准保留（没被点名的地方原样——P1 六字段全等，P2—P5 的分类、原文摘抄、转述全等）。另记一个宽口径，不进通过数：只看原文摘抄和分类没被动，允许转述换个说法——用来把"转述换了措辞"和"把原文摘抄改坏"分开。`--regrade <产物目录>` 可以不发请求、按现行判分规则重判已存的原始响应。

**结果（n=6，每家都走各自端点缺省的思考设置，输出预算取能力档案值）**：

| 模型 | 标准态四关全过 | 短卷四关全过 | 失分发次是什么 |
|---|---|---|---|
| deepseek-flash | 2/6（宽口径 5/6） | 6/6 | 标准态两条意见六发全落实，扣分全在"基准保留"：4 发顺手把没点名的转述改了措辞（"半衰期"写成"在人体内的半衰期"、"摄入"写成"摄入量"），其中 1 发还把 P3 的原文摘抄扩成了整句 |
| Ling-3.0-Flash | 6/6 | **3/6** | 短卷 1 发整份用 HopSchema 声明文法作答（`id % line = 'P1'` 这种形态，不是 YAML）；2 发把 L2 整句并进了 P2、P3 的原文摘抄（改动了没点名的地方） |
| Qwen3.8-27B（百炼 claude-code-proxy 端点） | 6/6 | 6/6 | 无 |
| qwen-flash | 5/6 | 6/6 | 标准态 1 发没交提取结果，交了一句"缺信息：无缺信息，可正常执行提取任务"（填错了输出槽） |
| glm-5.3-flash | 6/6 | 6/6 | 无（思考恒开，标准态六发共 208 秒、短卷共 547 秒） |

**怎么读这张表**：

- **上一节"27b 标准态 0/6"的结论已经过时**。同一个模型、同一个端点，今天的引擎标准态修订 prompt 下 6/6。9-18 以后引擎的修订供给改过多轮（修正块结构、形态教学），当时"框架压倒修正指令"的病在现行标准态里已经不再复现；9-18 那次的考卷是手拼的，已无法逐字复现对照，所以只能说"现行标准态下不再复现"，不能说清是哪一处改动治好的。
- **短卷不是对所有弱模型都有益**。Ling 在标准态 6/6，换短卷反而掉到 3/6——短卷砍掉了从头教学框架，也一并砍掉了对交付形态的完整教学，Ling 失去这层教学后犯了它已知的老病（把 HopSchema 声明文法当交付格式，G5 档案里有同型记录）。
- **deepseek 的标准态失分是"改多了"不是"改不动"**：两条意见全落实，只是顺手把没点名的转述改了措辞。按严口径这是失分（修订不许动没点名的地方），但危害轻——原文摘抄只有 1 发被动。短卷下它不改多。
- **qwen-flash 与 glm-flash 两档都能用**，qwen-flash 标准态有 1/6 的填错槽。qwen-flash 在真实任务里"修订意见不落实、谎报已改"的毛病是工具循环里的零工具调用（见档案 dims.tool_use），这张直连考卷没有工具环节，考不出那一类病——两件事不矛盾。

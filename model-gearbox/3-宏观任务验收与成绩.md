# 宏观任务验收与成绩（七个宏观任务 × 五个模型）

本文件回答两个问题，分两部分：

- **第一部分 逐格验收台账**：每个宏观任务 × 每个模型一格，每格要有一条真机定案；
- **第二部分 逐模型适配效果**：每个模型挂上变速箱适配之后能干成什么活、花多少钱，与适配前对照；
- 末尾是**销格记录**：每格的定案证据与验尸摘录，按任务分节。

模型的裸能力（不挂适配时的探针数据）不在这里，在 [[1-模型裸能力体检表]]；库里哪些 skill 需要给弱模型做定制版，在 [[2-skill适配需求清单]]。

## 第一部分：逐格验收台账

**判定标记**：

- ✅ 完赛：该模型在该任务可用，带完赛账与代价；
- ⚠️带伤：完赛但交付物有缺陷；
- ❌ 能力定案：必须附失败现场的回复原文（见下条硬闸）；
- ⛔ 环境原因：端点、账户这类我方控制不了的原因，不计能力账。

不合法的定案：被我方止损帽截停的跑、修复落地前旧机制下的跑、没排的格。

**❌ 定案的硬闸**：判 ❌ 之前必须验尸产出真身——把死亡步骤的回复原文关键段摘进销格记录，确认是模型真的没交出合格产出，而不是收割、切块、配置或端点把合格产出弄死了。只有引擎报错文案（SCHEMA_MISMATCH 报错里的"实际:"字段是解析器视角的截断，不是产出真身）、没有真身摘录的，只能记 ⛔待验尸，不许记 ❌。**格内的模型口径=该模型当主执行模型**（判官与终检按各任务既定路由，弱执行加强把关是设计内形态，不算作弊）。

**主要结论**：

1. **Ling、qwen27 两家被复查过的失败全部是工装账**（收割、切块、渲染、教学、spec 缺陷、引擎缺口、配置、端点），没有一格是能力墙。弱模型可用面的边界由工装质量决定。
2. **qwen-flash 母本直跑的共同病形是"该调工具时不调、直接编产出交卷"，但这个病能靠工装绕开**：把检索和网址照抄交给程序、模型只拟检索词和按编号挑选之后，fact check 与 deep research 翻成 ✅；ppt 靠母本补机械核对（每跑暴露的病都变成一条机检）翻成 ✅。绕不开的有两处：一是"对一份长草稿做精确的局部编辑"——hb2 修错步要逐字复制待替换的原文，qwen-flash 凭记忆写、对不上，教学和引擎提示最接近原文都没救回来；二是写 Python 校验脚本——标准拆解四跑每跑败在一个新的写法习惯上，补教学、加倍重试都没收敛。
3. **glm-5.3-flash 母本直跑没有一格 ❌，代价是慢和贵**：fact check S 档 83 万 tokens / 54 分钟，hb2 334 万。
4. **标准拆解的行为差别**：各家跑的是同一个环境、同一份 spec、同一套纯文件工具。缺执行能力时，deepseek 自己声明缺失并换路（用文件搜索对样例做了实际验证）；27b 与 Ling 认定 shell 一定存在，把预算烧在找入口上。差别是行为不是环境。修法是给引擎补执行能力：`run_script` 工具，加上 Bash 纪律句按工具面条件化（todo/0110，commit 5d2aad92）。另一条结论：规约把"实跑留痕"定成必填、环境又不给实跑手段时，连 deepseek 也会写出"退出码 0"这种没观测过的验证来源——编造是供给逼出来的，不是模型的诚信档位。

5. **构建能力的分档不随构建形态变**：同一份 incident 语料，引擎驱动的 hb2（任务 4）与纯自然语言的 hb1（4b 对照行）分出同一个格局——deepseek、glm、qwen27 能建，qwen-flash 两种形态都建不出可执行产物。hb1 没有引擎守停点，多考一项"自律"：qwen-flash 跳过了第二次终审，Ling 守住了停点却把知识文档引用写进注释、执行时注入不了。成本上 hb1 是 hb2 的 3—10 倍（Claude Code 每轮重发全上下文），只能比"能不能走完、产物对不对"，不比价。

### 口径

1. **第一部分管宏观任务面的完工**；能力维度的缺格不单列，归 [[1-模型裸能力体检表]]（G6 代码生成已由专用探针定档，标准拆解任务作真机旁证；G7/G8 在完工线外）；
2. **每格销格时同步两处**：本文件第二部分加行（适配前后对照），[[1-模型裸能力体检表]]刷格（若暴露新裸能力事实）；
3. 规约一律用库内现行版；测试 run 里的判断类停点（审批、终审意见等）由 agent 按该步判据代答。

## 第二部分：逐模型适配效果

**这一部分回答的问题**：一个模型裸测某项能力偏弱（[[1-模型裸能力体检表]]的账），挂上变速箱适配之后，它实际能完成什么档次的任务？花了什么代价？——体检表是"体检报告"，这一部分是"上岗成绩单"。

**读表口径三条**：

1. **"适配前"取该模型在该任务上无适配机制的真机实测**（不是推测），没有裸跑账的写"未裸测"；
2. **"适配后"只记真机完整任务完赛的账**，探针级验证不入这一部分（探针归体检表）；
3. **代价如实记**——适配不是免费的：并发冗余是倍数费用，切块是更多调用次数，路由强模型是单价上升。效果评价必须连着代价读。

### 二、跨模型的效果规律（消费面结论）

1. **适配的收益与模型档位成反比**：27b 从"五类不可用"翻到"五类可用"，Ling 补一档，deepseek 只省钱——变速箱的存在意义主要在弱档模型的可用化；
2. **"弱执行+强把关"是贯穿三档的正解形态**：27b 执行 + deepseek 判官（fc 变体）、构建归强 / 执行归弱（D98）、判官分层路由（dv）——同一思路在三个消费面各自落地；
3. **适配救得动的是形态病，救不动的是算力病**：提取覆盖（切块 + 并集治）、判官摇摆（封闭化治）、意见不收敛（方法 10 治）全部翻正；重推理、开放式判定、超大件判据保持三处是真实能力墙，正解恒为路由；
4. **代价必须进预算口径**：27b fc M 的 2.3 倍成本方差、Ling 开思考 ×10、并发并集 ×N——适配后的"可用"是带价签的可用，岗位表（体检表第四节）按性价比排首选，这一部分解释为什么。
